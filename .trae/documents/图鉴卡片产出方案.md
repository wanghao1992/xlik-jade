# 图鉴卡片产出方案

## 一、目标

为已有图鉴系统补上**卡片产出途径**。当前卡片只能靠 `-card` 调试命令发放，图鉴/羁绊无法通过正常游戏获得。

**用户确认的口径**：

1. **唯一来源 = 最终BOSS + 团队BOSS**：仅这两类 Boss 会被击败时**概率掉落 1 张卡片**（小怪 / 挑战怪 / 通关结算均不产出）。
2. **品质越高越难掉**：品质 1~5 按权重随机；品质 5（传说）权重极低，**基本只能通过已有「卡片合成」获得**。
3. **模式 / 难度影响**：既影响"是否掉落"，也影响掉落品质。
4. **到手形式 = 直接入账并播报**（同宝库/存档装备口径，无拾取操作）。

## 三、数据设计：改 `图鉴.lua`

在文件开头「〇、品质 / 合成配置」之后，新增掉落配置：

```lua
--==========================================================================
-- 〇₂、掉落配置(仅最终BOSS / 团队BOSS 掉落; 见 图鉴流程.lua 的 codexFlow.dropFromBoss)
--==========================================================================
--- 说明: 每次 Boss 被击败, 对每个在线玩家判一次"是否掉落"(掉则 1 张);
---   是否掉落 -> 来源基础概率 + 难度递增, 再乘模式倍率, 封顶 chanceCap;
---   掉落品质 -> 按 [难度档+模式档] 查 qualityRate 权重随机(品质越高权重越低);
---   品质 5(传说)权重最高仅 50‰(5%) -> 基本只能靠"卡片合成"(synthRate)获得。
codexData.drop = {
    --- 是否掉落的基础概率(万分比 0~10000), 按来源
    baseChance = { final = 5000, raid = 7000 },      -- 最终BOSS 50% / 团队BOSS 70%
    --- 难度每 +1 增加的概率(万分比)
    chancePerDiff = 150,                             -- +1.5%/级
    --- 概率上限(万分比)
    chanceCap = 9500,                                -- 95%
    --- 模式对"是否掉落"概率的倍率
    modeChanceMul = { ['正常模式'] = 1.0, ['进阶模式'] = 1.3, ['追击模式'] = 1.6 },
    --- 模式对"难度档"的额外上移(结果按 qualityRate 行数钳制)
    modeTierBonus = { ['正常模式'] = 0, ['进阶模式'] = 1, ['追击模式'] = 2 },
    --- 品质权重表: 行 = 难度档 T=floor((难度-1)/7)+1 (1..7, 对应难度 1..49); 列 = 品质 1..5
    ---   每行权重和 = 1000; 品质 5 权重极低(最高 50‰)
    qualityRate = {
        { 600, 320,  75,   5,  0 },   -- T1 难度 1-7
        { 520, 330, 130,  18,  2 },   -- T2 难度 8-14
        { 430, 340, 190,  35,  5 },   -- T3 难度 15-21
        { 330, 340, 250,  70, 10 },   -- T4 难度 22-28
        { 250, 320, 290, 120, 20 },   -- T5 难度 29-35
        { 170, 290, 330, 175, 35 },   -- T6 难度 36-42
        { 110, 250, 350, 240, 50 },   -- T7 难度 43-49
    },
}
```

**关键性质（自检）**：难度 1 正常模式 → 掉率 50%、品质档 T1（传说权重 0，掉不出）；难度 49 追击 → 掉率封顶 95%、品质档 T7（传说约 5%）。所有行权重和均为 1000。

## 四、逻辑设计：改 `图鉴流程.lua`

在「六、卡片合成」与「七、客户端请求」之间插入新的「七、卡片掉落（最终BOSS/团队BOSS）」，原客户端请求顺延为「八」。

> 复用本文件已有局部量/函数：`isValid`、`cardOf`、`GROUP_CARD`、`codexFlow.randomCardOf(q)`、`codexFlow.push(player, allowOpen)`。

```lua
--==========================================================================
-- 七、卡片掉落(仅最终BOSS / 团队BOSS)
--==========================================================================

--- 当前难度档(1..#qualityRate): floor((难度-1)/7)+1, 再叠加模式档加成并钳制
---@return number
local function dropTier()
    local cfg = codexData.drop or {}
    local diff = math.max(1, math.floor(tonumber(game.selected and game.selected.difficulty) or 1))
    local tier = math.floor((diff - 1) / 7) + 1
    tier = tier + ((cfg.modeTierBonus or {})[game.selected and game.selected.mode] or 0)
    return math.max(1, math.min(#(cfg.qualityRate or {}), tier))
end

--- 本次掉落的触发概率(万分比 0~10000)
---@param source string 'final'|'raid'
---@return number
function codexFlow.dropChance(source)
    local cfg = codexData.drop or {}
    local diff = math.max(1, math.floor(tonumber(game.selected and game.selected.difficulty) or 1))
    local chance = ((cfg.baseChance or {})[source] or 0) + (diff - 1) * (cfg.chancePerDiff or 0)
    chance = math.floor(chance * ((cfg.modeChanceMul or {})[game.selected and game.selected.mode] or 1))
    return math.max(0, math.min(cfg.chanceCap or 10000, chance))
end

--- 按权重表随机产出本次掉落品质(1..5)
---@return number
function codexFlow.rollDropQuality()
    local cfg = codexData.drop or {}
    local row = (cfg.qualityRate or {})[dropTier()] or {}
    local maxQ = codexData.qualityMax or 5
    local total = 0
    for i = 1, maxQ do total = total + (row[i] or 0) end
    if (total <= 0) then return 1 end
    local r, acc = math.rand(1, total), 0
    for i = 1, maxQ do
        acc = acc + (row[i] or 0)
        if (r <= acc) then return i end
    end
    return 1
end

--- 对单个玩家判一次掉落(概率 -> 品质 -> 品质内随机一张 -> 入账 + 播报 + 刷新面板)
---@param player Player
---@param source string 'final'|'raid'
---@return boolean dropped
---@return table|nil info { id, name, quality }
function codexFlow.dropFromBoss(player, source)
    if (false == isValid(player) or true ~= player:isPlaying()
        or false == class.isObject(player.hero, UnitClass)) then
        return false, nil
    end
    if (math.rand(1, 10000) > codexFlow.dropChance(source)) then
        return false, nil
    end
    local q = codexFlow.rollDropQuality()
    local id = codexFlow.randomCardOf(q)
    if (nil == id) then
        return false, nil
    end
    saveArchive.add(player:handle(), GROUP_CARD, id, 1)
    local c = cardOf(id) or {}
    local qc = (codexData.qualityColor or {})[q] or ''
    local qn = (codexData.qualityName or {})[q] or ''
    alerter.message(player, ('|cffffff00[图鉴]:掉落|r|cffffff00了|r%s|r|cffffff00[%s]!!!|r'):format(
        qc .. tostring(c.name or '?'), qn))
    codexFlow.push(player, false)
    return true, { id = id, name = c.name, quality = q }
end

--- 某个 Boss 被击败: 对全体在线玩家各判一次掉落(单人各判, 互不影响)
---@param source string 'final'|'raid'
---@return number dropped 本局掉落玩家数
function codexFlow.onBossDead(source)
    sync.must()
    local dropped = 0
    for i = 1, player.startQuantity do
        local ok = codexFlow.dropFromBoss(Player(i), source)
        if (true == ok) then dropped = dropped + 1 end
    end
    return dropped
end
```

在文末（与既有 `sync.receive` 同区）追加两条事件监听：

```lua
--- 最终BOSS被击败(通关当刻) -> 卡片掉落(事件由 通关失败.lua 的 gameResult.win 广播)
event.syncRegister("player", "slkc_game_clear", "codex_final_drop", function(syncData)
    codexFlow.onBossDead("final")
end)

--- 团队BOSS被击败 -> 卡片掉落(事件由 存档挑战.lua 的 startRaid 死亡回调广播; 与宝库同源)
event.syncRegister("player", "团队BOSS死亡", "codex_raid_drop", function(syncData)
    codexFlow.onBossDead("raid")
end)
```

## 五、调试命令：改 `command.lua`

在 `LK_DEBUG` 段内、`-card` 命令之后新增（用于验证概率/品质分布，因真实掉落随机且最终BOSS在实测里难复现）：

```lua
--- -carddrop [final|raid] [次数] 模拟一次 Boss 掉落判定(测试用; 含概率)
---   默认 final / 1 次; 次数用于快速观察概率与品质分布
---@see process/图鉴流程.lua 的 codexFlow.dropFromBoss / dropChance
player.command("^-carddrop[ ]*%a*[ ]*%d*$", function(evtData)
    local pla = evtData.triggerPlayer
    local cds = string.explode(" ", string.trim(evtData.chatString))
    local source = (cds[2] == 'raid') and 'raid' or 'final'
    local times = math.max(1, tonumber(cds[3]) or 1)
    local dropped = 0
    for _ = 1, times do
        if (true == codexFlow.dropFromBoss(pla, source)) then dropped = dropped + 1 end
    end
    alerter.message(pla, ('[图鉴]模拟 %s Boss 掉落 %d 次, 掉落 %d 张(单次概率 %d%%)'):format(
        source, times, dropped, math.floor(codexFlow.dropChance(source) / 100)))
end)
```

## 六、决策与假设

| 项 | 决定 |
|---|---|
| 产出途径 | **仅** 最终BOSS 与 团队BOSS；小怪/挑战怪/通关结算不产出 |
| 挂接方式 | 复用现有事件：最终BOSS → `slkc_game_clear`（= `gameResult.win()`，即最终BOSS被击败当刻）；团队BOSS → `团队BOSS死亡`。**不改 BOSS.lua / 存档挑战.lua** |
| 掉落次数 | 每个 Boss 每次被击败，对每个在线玩家**各判一次**，成功掉 **1 张**（与 宝库「按人数」不同，不吃带人数加成） |
| 概率模型 | `min(封顶, 基础[来源] + (难度-1)×每级增量) × 模式倍率`，万分比 |
| 品质模型 | 难度档 `T=floor((难度-1)/7)+1`（1..7）+ 模式档加成，查 `qualityRate` 权重随机；品质 5 权重最高 5%，低难度为 0 → 传说基本只能靠合成 |
| 卡片选取 | 命中品质后，在该品质内用已有 `codexFlow.randomCardOf(q)` 均匀随机 |
| 到账 | `saveArchive.add(handle,'图鉴卡牌',id,1)` + `alerter.message` 播报 + `codexFlow.push(player,false)`（面板开着则刷新） |
| 调试 | 新增 `-carddrop [final\|raid] [次数]`（`LK_DEBUG`） |
| 新资源/新文件 | 无 |

## 八、验证步骤

1. **语法**：对本方案涉及的 3 个 `.lua` 跑 `loadfile`（本机 Lua 5.1）确认无语法错误。
2. **构建**：`xlik.exe run demo -l!` 通过（无新增资源，应无 `【图片】... 不存在` 报错）。
3. **实机·低难度**（正常模式 N1）：`-carddrop final 20` → 约 10 张（≈50%），且**不会出现传说**（T1 传说权重 0）。
4. **实机·高难度/模式**：切到高难度/追击模式后 `-carddrop raid 50` → 掉率明显升高（封顶 95%），并可见高品质（含少量传说）。
5. **实机·真实入口**：
   - 通关（击杀最终BOSS）当刻 → 图鉴页出现新卡数量、播报「[图鉴]:掉落了……」，羁绊页配方 `have` 同步增加。
   - 通关后挑战团队BOSS并击杀 → 同样掉落与播报。
6. **面板联调**：打开图鉴（F6）时触发掉落 → 面板不报错且数量刷新（`push(player,false)`）。
7. **回归**：宝库团队BOSS掉落（`bao_raid_drop`）、存档通关奖励（`save_flow_clear`）不受影响（新增监听为独立 key，互不干扰）。
