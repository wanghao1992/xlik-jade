# 主动天赋技能手动选目标 · 实现计划

## Context（为什么改）

主动天赋（剑气 / 天雷 / 天降斩 / 剑阵 / 御剑 / 霸斩）当前是「点击技能槽或按 1~5 热键 → 直接同步给服务端 → `talentFlow.castSlot` 自动索敌释放」，没有普通技能那套选目标流程，所以既看不到施法距离圈/作用范围圈，也无法指定方向或目标。

本次把其中 4 个改成手动选目标：

| 技能 | 目标类型 | 施法距离口径 | 作用范围圈 |
| --- | --- | --- | --- |
| 剑气 qi1 | 点目标(loc) | `剑气距离` or 1500 | 无（直线技能） |
| 剑阵 sword1 | 点目标(loc) | `剑阵射程` or 1500 | `剑阵半径` or 180，圈在英雄脚下 |
| 天降斩 leap1 | 单位目标(unit) | `跳劈索敌` or 800 | `跳劈斩击范围` or 450，圈在目标处 |
| 霸斩 omni1 | 单位目标(unit) | `霸斩索敌` or 900 | `霸斩半径` or 500，圈在目标处 |

天雷（自身雷暴，化身在英雄位置）、御剑（飞行状态 + 右键转向）保持现状。
超出施法距离时**拒绝施放并提示**，不做自动走近。自动释放（右键开启）继续走原自动索敌逻辑。

## 方案总览

```
点击槽位 / 按热键
  ├─ 该技能有 targetMode 且未开自动
  │    → cursor.quote("talent_loc" / "talent_unit", {slot, entry})
  │    → 显示距离圈 + 作用圈，左键确认 → sync.send("xlik_talent_cast", {p, slot, mode, x, y / unitId})
  │    → 服务端校验范围/目标 → talentFlow.castSlot(player, slot, opt) → castX(hero, opt)
  └─ 无 targetMode 或已开自动
       → 维持现状 sync.send("xlik_talent_cast", {p, slot})
```

## 改动清单

### 1. 天赋元数据 [天赋-90-主动技能.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/ability/天赋-90-主动技能.lua)

给 `ACTIVE_TALENTS` 四个条目增加（纯读 `hero._attr`，不新增文件级 local）：

- `targetMode = "loc" | "unit" | nil`
- `range(hero)` / `area(hero)` / `areaAnchor = "self" | "target"`
- 剑气：`area = nil`（直线，不画作用圈）
- 天雷 / 御剑：不设 `targetMode`

新增对外查询函数（均实时读全局 `talentFlow.*`，避免文件加载顺序问题）：

- `talentFlow.targetInfo(hero, entry)` → `{mode, range, area, areaAnchor}`
- `talentFlow.isTalentUnitTarget(hero, entry, unit)` → 存活 / 非建筑 / 敌对
- `talentFlow.checkTalentTarget(hero, entry, opt, grace)` → `ok, "range"|"target"|nil`

### 2. 服务端施放链 [天赋.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/ability/天赋.lua)

- 抽出纯读校验 `talentFlow.checkSlot(player, slot)` → `t, hero, reason`，覆盖：玩家/英雄存活、槽位范围、槽位内容、天赋等级、冷却、互斥 `blocked`、蓝耗。原 `castSlot` 与指针 `start` 共用，避免两套判断。
- `talentFlow.castSlot(player, slot, opt)` 增加可选 `opt`：
  - `opt == nil` → 原自动逻辑（自动释放、旧调用不受影响）
  - `targetMode` + `opt` → `checkTalentTarget`，失败返回 `false, reason`
  - 成功才扣蓝 / 写冷却
  - 服务端范围容差 `+64`，抵消同步延迟中的位移
- `sync.receive("xlik_talent_cast")` 扩展参数（`|` 拼接，仅 number/string）：
  - `{playerIndex, slot}`：自动/兼容
  - `{playerIndex, slot, "loc", x, y}`
  - `{playerIndex, slot, "unit", unitId}`（用 `class.i2o` 解析）
  - 仅 `range/target` 失败时 `alerter.message` 提示；冷却/蓝耗保持静默（UI 已灰显）
- `activeSlots` 返回值增加 `targetMode`，供 UI 判断是否进入选目标。

### 4. 客户端指针 [setup/cursor.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/setup/cursor.lua)

- 泛化现有绘制（不改变普通技能行为）：
  - `showAreaAt(radius, x, y)`：从 `areaPreview` 抽出
  - `showRangeRing(unit, distance, tx, ty)`：从 `castRangeRing` 抽出
  - 保留 `MAX_INDICATOR_RADIUS = 5000` 守卫
- `rangeFollowStart` 的计时器支持 `data.hero`（天赋）与 `data.ability:bindUnit()`（普通技能）两种来源，避免天赋 quote 取 nil。
- 新增两个自定义 quote：`"talent_loc"` / `"talent_unit"`，data = `{slot, entry}`：
  - `start`：`PlayerLocal().hero` 存活 → `talentFlow.checkSlot` → 槽位内容未变 → `cursorLock()` + `rangeFollowStart()` + 播放点击音；失败提示原因并 `return false`
  - `refresh`：英雄死亡/槽位变化/不可施放 → `quoteOver()`；`mouse.isSafety` 为 false 隐藏所有圈；距离圈以英雄为圆心、半径 `range`；`talent_loc` 的作用圈在鼠标点，`talent_unit` 按 `areaAnchor` 在悬停单位或英雄处；悬停敌方单位高亮（独立 local，不复用 `_unit1`）
  - `leftClick`：先 `mouse.isSafety`，再判断是否点在 `xlik_skillbar` 的 `bar:isInside` 上（是则直接 `quoteOver()`，防止在技能槽下方误施放）；`checkTalentTarget` 失败 → 提示并**保持选目标**；成功发送同步并 `quoteOver()`
  - `rightClick`：`quoteOver()` 取消
  - `over`：清指针、隐藏圈、`cursorUnLock()`、恢复高亮
- 普通技能 quote 不做行为改动。

### 5. 技能槽 UI [xlik_skillbar/main.lua](file:///d:/Lua/xlik-jade/vendor/assets/war3mapUI/xlik_skillbar/main.lua)

- `ui:castSlot(index)`：
  - 取 `talentFlow.activeSlots(p)[index]`
  - 若 `targetMode` 存在且未开自动 → `talentFlow.checkSlot` 通过后 `cursor.quote("talent_"..mode, {slot=index, entry=key})`，否则提示原因
  - 其余情况维持 `sync.send("xlik_talent_cast", {p:index(), index})`
  - 热键与左键共用此入口，右键自动释放不变
- 悬停 tooltip 追加提示：「左键/热键：点击后选择方向/目标」；自动模式仍提示右键取消。

## 关键边界

1. **技能槽无 UIBlock**：`mouse.isSafety` 在技能条上仍为 true，必须 `bar:isInside(rx, ry)` 判定，否则会点在槽位下方的地图上。
2. **目标在点击前失效**：`leftClick` 与 `castSlot` 都重新取单位/校验，失败提示「目标无效」，不扣蓝/CD。
3. **点位退化**：点位距离 ≤ 1 时退回英雄面向，避免 `vector2.angle` 退化。
4. **自动释放**：`autoCastTick` 与“开启即释放”均传无 opt，必须走自动分支，不能因 `targetMode` 被拦截。
5. **`fireSwordQi` 是导出 API**：只加参数不改旧参数顺序。
6. **加载顺序**：`setup/cursor.lua` 与 `天赋-90` 顺序不确定，回调内实时读 `talentFlow.*`。
7. **200 局部上限**：`天赋.lua`、`天赋-60` 不新增文件级 local。

## 验证步骤

1. `-tf` 加天赋点，学会 qi1 / sword1 / leap1 / omni1。
2. 按热键与点击槽位：应进入选目标，显示英雄距离圈 + 对应作用圈；英雄移动时距离圈跟随。
3. 圈内点击：剑气朝点方向发射、剑阵朝点方向展开、天降斩跳向选中敌人、霸斩以选中敌人起手。
4. 圈外点击：圈变红、提示「超出施法距离」、不扣蓝/CD、可重试。
5. 友军/建筑/自己：提示「目标无效」。
6. 右键：取消选目标。
7. 右键槽位开自动：不再进入选目标，按原自动索敌节奏释放；取消自动后恢复手动。
8. 天雷/御剑：行为不变，无选目标圈。
9. 瞄准时点击技能槽/小地图/其他面板：不会在对应地图位置误施放。
10. 冷却/蓝不足时按热键：不进入选目标，提示原因。
