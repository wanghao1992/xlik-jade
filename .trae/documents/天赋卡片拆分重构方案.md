# 天赋系统重构方案（卡片拆分 + 两级依赖 + 点数收敛）

## 一、摘要

当前 11 个天赋把「基础成长 + 若干里程碑附加效果」打包成一张卡，40 级里绝大多数效果要玩家一直点到高等级才解锁；同时「天赋挑战」奖励 `(等级-1)//8+1` 点，随挑战等级线性膨胀，点数过剩。

本次重构：

1. **拆分**：把每个里程碑附加效果拆成独立的 **1 级「效果卡」**，再为每张效果卡配一张 **1 级「增强卡」**；原「基础成长卡」保留多级。形成 **基础卡（多级）→ 效果卡（1级）→ 增强卡（1级）** 的两级依赖结构。
2. **收敛点数**：天赋挑战奖励改为 **固定 +1 点**。
3. **三选一**：发动天赋技能仍是三选一，但候选池换成拆分后的全部卡片；**移除「快速加点」模式**，只保留三选一。

已确认的设计选择：

| 项 | 决定 |
| --- | --- |
| 拆分粒度 | 基础卡多级 + 附加效果各成 1 级卡 + 效果卡的增强卡 |
| 依赖关系 | 两级依赖：效果卡需先学对应基础卡；增强卡需先学对应效果卡 |
| 快速加点 | 移除，只保留三选一 |
| 点数来源 | 仅天赋挑战改为固定 +1；转职+1、引导+1、积分道具「天赋卷轴」开局+3 不变 |

## 三、方案总览

拆分后共 **43 张卡**：11 张基础/机制卡（多级） + 16 张效果卡（1 级） + 16 张增强卡（1 级）。

- **基础/机制卡**：原 11 张卡保留，但 4 张主力卡的里程碑附加效果被移出（不再在 5/10/…/40 级追加），只保留每级基础数值。7 张机制卡逻辑不变。
- **效果卡**：由主力卡的 4 组里程碑效果拆出（每组含 1 张效果卡 + 1 张增强卡），共 4 族 × 4 组 = 16 张效果卡。
- **增强卡**：每张效果卡对应一张 1 级增强卡，用于承载原「第二个档位」的数值（如攻速 5 级+20% → 15 级+30%）。

**候选池规则**（替换 `availableTalents`）：卡片满足「未满级」且「前置已满足（`req.key` 的等级 ≥ `req.level`）」才进入候选池。效果卡前置 = 对应基础卡 ≥ 1 级；增强卡前置 = 对应效果卡 ≥ 1 级；基础/机制卡无前置。

**效果应用**：改为「按卡片 key 派发」的处理器表 `TALENT_EFFECTS[key]`，`learnOne` 升级时逐级调用；1 级卡学会即应用一次，学会后 `level` 达到 `levelMax` 自动退出候选池。

**(2) 前置校验工具**（新增）：

```lua
--- 卡片前置是否满足(基础/机制卡无 req -> 恒满足)
---@param player Player
---@param def table
---@return boolean
local function reqMet(player, def)
    local req = def.req
    if (nil == req) then
        return true
    end
    return talentLevel(player, req.key) >= (req.level or 1)
end
```

`availableTalents` 改为同时过滤「未满级」与 `reqMet`：

```lua
local function availableTalents(player)
    local pool = {}
    for _, d in ipairs(TALENT_DEFS) do
        if (talentLevel(player, d.key) < d.levelMax and reqMet(player, d)) then
            pool[#pool + 1] = d
        end
    end
    return pool
end
```
