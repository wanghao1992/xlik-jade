# 挑战怪改为「UI按钮手动生成 + 单人独享追击」改造方案

## 一、目标概述（Summary）

在现有「四角挑战」系统基础上，把挑战怪的**出生逻辑**从「地图四角常驻自动刷新」改为「UI 按钮手动在英雄身旁生成」：

1. 新增（复用现有）一个 UI 套件 `slkc_challenge`，显示 **4 个挑战按钮**（金币 / 经验 / 天赋 / 宝物）。
2. 点击按钮或按快捷键时，**在触发玩家的英雄当前位置旁**生成对应类型的挑战怪。
3. 挑战怪**全图追击触发它的那名玩家**（追击模式手感），直到死亡。
4. **完全取代**四角常驻自动刷新（移除开局四角各刷一只 + 击杀后 30 秒重生）。
5. **单人独享**：挑战怪只追击触发者，击杀后的奖励（现有四类：金币 / 经验 / 天赋点 / 宝物自选）**只发给触发者**（不再全队发放）。
6. 四个按钮快捷键分别为 **Alt+1 / Alt+2 / Alt+3 / Alt+4**。

## 三、改造方案（Proposed Changes）

### 3.1 改写：`vendor/assets/war3mapUI/slkc_challenge/main.lua`（4 个挑战按钮）

**为什么**：提供 4 个挑战按钮 + Alt+1~4 快捷键，点击后通知服务端在英雄旁生成挑战怪。

**怎么做**：
- 保留套件名 `slkc_challenge` 与底部左侧布局（沿用原 `PX_W/PX_H/BTN_W/BTN_H/BTN_GAP/BTN_X/BTN_Y` 口径），4 个按钮横向排列（第 2~4 个依次排在右侧）。
- 定义 4 个入口（示例）：

```lua
local ALT = { keyboard.code["Alt"] }
local ENTRIES = {
    { key = "gold",     text = "金币挑战", hotkey = "1", symbol = "挑战按钮-金币挑战" },
    { key = "exp",      text = "经验挑战", hotkey = "2", symbol = "挑战按钮-经验挑战" },
    { key = "talent",   text = "天赋挑战", hotkey = "3", symbol = "挑战按钮-天赋挑战" },
    { key = "treasure", text = "宝物挑战", hotkey = "4", symbol = "挑战按钮-宝物挑战" },
}
```
- 每个按钮：`UIBackdrop(...LK_SLKC_BUTTON_PANEL) + UIButton`，`:text(...)`、`:hotkey(keyboard.code[hotkey], ALT, cb)`、`:onEvent(eventKind.uiLeftClick, key, cb)`。
- `cb` 统一：`sound.vcm("war3_MouseClick1"); sync.send(symbol, { PlayerLocal():index() })`。
- 按钮默认**可见**；提供 `ui:show(flag)`（同时开关面板与 `visible` 标志，隐藏时点击/热键一并失效，口径同原实现）。

### 3.3 改写：`projects/demo/scripts/globals/setup/四角挑战.lua`（核心）

**为什么**：出生逻辑由「四角常驻」改为「按钮手动 + 英雄旁 + 单人追击 + 单人奖励」。

**保留不动**：所有数值倍率表与公式（`RES_MUL1/RES_MUL2/RES_GOLD_LIST/RES_EXP_LIST`、`resourceLife/Defend/Attack/Gold/Exp/Talent`、`RS_*/rebirthLife/Defend/Attack`）、常量 `MONSTER_OWNER=6`、`MONSTER_FACE=270`、`MONSTER_STAT_MUL=1.5`、`clearAll/setup` 的通关清除框架、通关广播行为。

**改动**：
1. `cornerChallenge.corners`（含角落坐标）→ 改为 `cornerChallenge.types`（去掉 `x/y`，加 `symbol`）：
   ```lua
   cornerChallenge.types = {
       { key='gold',     name='金币挑战', family='resource', reward='gold',     symbol='挑战按钮-金币挑战' },
       { key='exp',      name='经验挑战', family='resource', reward='exp',      symbol='挑战按钮-经验挑战' },
       { key='talent',   name='天赋挑战', family='resource', reward='talent',   symbol='挑战按钮-天赋挑战' },
       { key='treasure', name='宝物挑战', family='rebirth',  reward='treasure', symbol='挑战按钮-宝物挑战' },
   }
   ```
2. 状态表：`cornerChallenge.monsters` 改为按类型 + 玩家索引存放：`monsters[key][playerIndex] = Unit`；`kills[key]` 保留（决定下次等级）。删除 `cornerChallenge.timers`、`RESPAWN_DELAY`。
3. `createMonster(tp, level)`：签名由 `(corner, level)` 改为 `(tp, level)`，内部逻辑与属性口径**完全沿用**（资源族/转生族、进阶/追击分支、暴击技能、`move(400)`）；仅坐标来源改变（见下），并把 `attackRangeAcquire(800)` 调整为 **全图索敌**（追击手感）：`monster:attackRangeAcquire(99999)`。
4. 新增 `cornerChallenge.spawnForPlayer(key, player)`：
   - 守卫：`cornerChallenge.stopped == true` 或 `game.pass == true` 直接 return；`game.selected.mode == '温泉模式'` 时提示并 return。
   - 校验 `player` 有效、`hero` 存在且存活；若 `monsters[key][pi]` 仍是存活怪 → 提示「该挑战怪仍在追击中」并 return（防止刷屏/无限堆积）。
   - `level = (game.selected.difficulty or 1) + (cornerChallenge.kills[key] or 0)`（沿用原等级口径）。
   - 坐标 = 英雄旁：`local sx, sy = vector2.polar(hero:x(), hero:y(), 200, math.rand(0, 359))`。
   - `local monster = createMonster(tp, level)` 在 `(sx, sy)` 生成，`monster:name(tp.name)`，登记 `monsters[key][pi] = monster`。
   - 单人追击锁定：
     - `J.RemoveGuardPosition(monster:handle())`（关闭守卫回撤，实现全图追）；
     - `monster:orderAttackTargetUnit(hero)`（立即锁定触发者）；
     - 反抢目标：`monster:onEvent(eventKind.unitBeforeAttack, "challenge_lock", function(evt) 若 evt.targetUnit ~= hero 则 monster:orderAttackTargetUnit(hero) end)`；
     - 兜底重锁：`async.setInterval(1, ...)` 每 1 秒（怪物存活、英雄存活、且怪物与英雄距离 > 怪物攻击范围时）重新 `orderAttackTargetUnit(hero)`；怪物死亡/`clearAll` 时销毁该计时器。
   - 死亡回调 `monster:onEvent(eventKind.unitDead, ...)`：
     - 清 `monsters[key][pi]`、销毁重锁计时器；
     - **只给触发者发奖**：`giveReward(tp, level, player)`（改为单玩家版本，逻辑同原 `giveReward` 但只处理 `player`；不再遍历全队）；
     - `kills[key] = kills[key] + 1`；
     - 广播（逐玩家语义保留）：`async.call(player, function() sync.send('玩家-击破四角挑战怪', { player:index() }) end)`（供引导第 3 步）。
   - 注意：**不再有 30 秒重生**。
5. `giveReward(corner, level)` → `giveReward(tp, level, player)`：只处理传入的单个玩家，奖励类型分支与文案沿用原样本（金币/经验/天赋/宝物自选）。
6. `cornerChallenge.setup()`：
   - 遍历 `cornerChallenge.types`，为每个 type 注册：`sync.receive(tp.symbol, function(syncData) cornerChallenge.spawnForPlayer(tp.key, Player(syncData.transferData[1])) end)`；
   - 保留通关清除：`event.syncRegister("player", "slkc_game_clear", "corner_challenge_clear", cornerChallenge.clearAll)`。
7. 删除 `cornerChallenge.spawnAll()`（不再开局四角刷怪）。
8. `cornerChallenge.clearAll()`：改为遍历 `monsters[key][pi]` 全部销毁 + 清空 + 销毁所有重锁计时器 + `stopped = true`（去掉 corners/timers 相关）。
9. `cornerChallenge.firstAlive()`：改为遍历所有 `monsters[key][pi]` 返回第一个存活怪（供引导选中；无自动刷怪时可能返回 nil，引导已做兜底）。

## 四、假设与决策（Assumptions & Decisions）

1. **完全取代**：移除四角常驻自动刷新（开局 4 只 + 30 秒重生），只保留按钮手动生成（用户已确认）。
2. **单人独享**：挑战怪只追击触发者（`orderAttackTargetUnit(触发者)` + 反抢/重锁），奖励**只发给触发者**（用户已确认）。
3. **奖励口径**：沿用现有四类奖励（金币 / 经验 / 天赋点 / 宝物自选），不新增其它资源（用户已确认「资历」即现有四类奖励）。
4. **等级基准**：`level = 当前难度 + 该类型累计击杀数`（沿用原 `challengeLevel` 口径；如需固定为难度，只需改这一行）。
5. **防刷**：同一玩家、同一类型若已有存活挑战怪，本次点击不重复生成（仅提示）。这是为防止无限堆积的最小约束；如需允许同时多只，删掉该守卫即可。
6. **模式限制**：温泉模式不生成挑战怪（与现有「温泉不刷怪」一致），并隐藏挑战面板。
7. **不做**：不执行打包/游戏内测试（按用户约定）；仅做静态检查（`luac -p`）。
8. 原 `slkc_challenge` 的旧同步名（`挑战按钮-资源挑战` / `挑战按钮-转生挑战`）已被 `sync.receive` 移除，不再作为入口。
