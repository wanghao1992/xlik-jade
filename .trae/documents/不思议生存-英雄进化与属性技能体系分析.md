## 0. 一页结论

### 最值得借鉴（按优先级）

| 优先级 | 借鉴点 | 一句话价值 | 当前项目成本 |
|---|---|---|---|
| P0 | 候选重随（消耗次数） | 把「随机」变成「可管理的随机」，减少开局被烂职业锁死的挫败 | 低（面板 + 一个计数字段） |
| P0 | 进化状态锁 | 进化期间锁操作，避免面板打开时英雄走位/被秒/技能错乱 | 低（一个 Buff + 6 条限制） |
| P0 | 取消进化 / 手动进化开关 | 给玩家「这次不换」的权利，降低强制换职业的负体验 | 低（沿用现有流程字段） |
| P1 | 职业稀有度分层 + 加权池 + 保底 | 让 42 个职业形成梯度，长期目标与惊喜感来源 | 中（打标 + 权重表 + 抽取器） |
| P1 | 图鉴熟练度（跨局成长） | 复用已有图鉴存档，做「玩得多就变强」的长期留存 | 中（存档字段 + 加成应用） |
| P2 | 成长 / 进化增幅属性 | 让数值成长有「滚雪球」层次，支撑长局 | 中高（需接框架升级流程） |

### 不建议照搬

1. **`hero:transformat()` 整单位替换**：源项目靠引擎替换单位类型，当前项目的差量迁移更适合自研框架，且能保留物品/天赋/等级，不要退回整体替换。
2. **73 个英雄 × 四档位的内容体量**：当前 42 职业已有内容成本，分层应做「标签 + 权重」，不必扩成四套独立目录。
3. **位掩码 `disable_list` 与隐藏分支**：源项目用位运算禁用英雄、用「是否拥有 `效果-英雄技能[3]`」隐式切换 SSR 池，可读性差，建议改成显式配置表。

## 2. 进化 / 转职系统拆解

### 2.1 触发层：经验驱动 vs 杀敌驱动

源项目是**等级 + 经验驱动**：

| 环节 | 行为 |
|---|---|
| 经验来源 | 每击杀 1 单位 +1 经验，乘以玩家「经验加成%」（[英雄配置.lua:78-85](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E9%85%8D%E7%BD%AE/%E8%8B%B1%E9%9B%84%E9%85%8D%E7%BD%AE.lua)） |
| 升级需求 | `50 / 200 / 500 / 800 / 1000 / 1500 / 2000 / 2500 / 3000 / 4000 / 5000`，30 级后需求 0（[英雄配置.lua:34-53](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E9%85%8D%E7%BD%AE/%E8%8B%B1%E9%9B%84%E9%85%8D%E7%BD%AE.lua)） |
| 满经验 | 自动模式（`设置:手动进化=0`）：`当前经验` setter 内直接 `add_hero_level(1,true)`，只升级不换英雄（[英雄配置.lua:16-31](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E9%85%8D%E7%BD%AE/%E8%8B%B1%E9%9B%84%E9%85%8D%E7%BD%AE.lua)）；手动模式：经验被夹在上限，由玩家点击「进化」技能触发 `单位-单位进化`（[等级属性.lua:180-190](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%8A%80%E8%83%BD/%E7%89%B9%E6%AE%8A/%E7%AD%89%E7%BA%A7%E5%B1%9E%E6%80%A7.lua)） |
| 手动/自动开关 | `设置:手动进化=0` 为自动；英雄 8 级且处于自动模式时，自动切回手动并提示「可在左下角关闭手动进化」（[单位进化.lua:203-208](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)） |

当前项目是**累计杀敌驱动**：`totalKill` 每杀 +1，门槛 `{30, 200, 400, 600, 700}`，达标后 `jobFlow.start`；击杀消耗的 `kill` 不影响进度（[刷怪.lua:296-326](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E5%88%B7%E6%80%AA.lua#L296-L326)）。

**判断**：杀敌驱动更适配「波次生存 + 割草」的当前项目，不建议改成经验驱动；但源项目的**手动进化开关**值得借：玩家可以在「想换职业」和「只想变强」之间切换，而不是只能二选一永久关闭。

### 2.2 候选层：稀有度四档 + 加权池

源项目 [单位进化.lua:56-100](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)：

| 档位 | 数量 | 档位权重 | 单位命名 |
|---|---|---|---|
| N级英雄 | 14 | 70 | `N级英雄[1..14]` |
| R级英雄 | 14 | 22 | `R级英雄[1..14]` |
| SR级英雄 | 16 | 6 | `SR级英雄[1..16]` |
| SSR级英雄 | 29 | 2 | `SSR级英雄[1..29]` |

- 权重池是**两层**：先按档位权重 `pick()` 出档位，再在档位内等概率 `pick(true)`；某档抽空后自动 `remove` 档位（[单位进化.lua:17-33](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）。
- 玩家有四项可叠加的档位权重属性：`N英雄几率 / R英雄几率 / SR英雄几率 / SSR英雄几率`（[单位进化.lua:11-16](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)），即稀有度可以**被成长属性倾斜**（运气/通关奖励可以改权重）。
- 候选数量 `clamp(玩家「英雄选择数量」, 3, 6)`；抽到 1 个直接进化，否则弹面板（[单位进化.lua:142-168](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）。
- **排除规则**（[单位进化.lua:101-133](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）：
  1. 当前英雄；
  2. 当前天赋绑定的英雄（避免重复拿同一套天赋）；
  3. 配置 `disable_list` 中被位掩码禁用的英雄。
  注：`使用过的英雄` 只做记录，**不参与**排除（[单位进化.lua:198-201](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）。
- **保底**（[单位进化.lua:134-141](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）：
  - 英雄 5 级且 `VIP4` 等级 > 0 → 至少 1 个 SSR；
  - 拥有 `效果-英雄技能[3]` Buff → 只从 SSR 池抽（**隐式分支，可读性差**，不建议照搬这种写法）。

当前项目：42 职业扁平池，`roll()` 等概率抽 `1 + 可选转职数量` 个，只排除当前职业（[转职.lua:137-153](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E8%BD%AC%E8%81%8C.lua#L137-L153)）。

### 2.3 交互层：三选一 / 重随 / 取消

面板结构（[背景板.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E7%95%8C%E9%9D%A2/%E8%8B%B1%E9%9B%84%E8%BF%9B%E5%8C%96/%E8%83%8C%E6%99%AF%E6%9D%BF.lua)）：

```
[英雄卡 ×6]  图标 / 名称 / 主要属性 / 所属类型 / 技能图标 / 天赋图标
[重新随机(n)] [取消进化]
[替换天赋：天赋显示[1..4]]  ← 选中英雄后再展开
```

关键交互（[事件处理.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E7%95%8C%E9%9D%A2/%E8%8B%B1%E9%9B%84%E8%BF%9B%E5%8C%96/%E4%BA%8B%E4%BB%B6%E5%A4%84%E7%90%86.lua)）：

- **点卡片**：隐藏其它卡，若该英雄只有 1 个可用天赋则直接确认，否则展开「替换天赋」4 选 1。
- **重随**：`param <= 0` 直接 return，否则消耗 1 次「英雄重随」并重抽整套候选（[单位进化.lua:210-213](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）。
- **取消进化**：英雄 < 7 级不允许；≥7 级可取消，`当前经验` 减半，保留原英雄，并派发 `单位-完成进化` 解除状态锁（[事件处理.lua:87-104](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E7%95%8C%E9%9D%A2/%E8%8B%B1%E9%9B%84%E8%BF%9B%E5%8C%96/%E4%BA%8B%E4%BB%B6%E5%A4%84%E7%90%86.lua)、[单位进化.lua:214-225](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）。
- **取消惩罚的设计意图**：不是「免费反悔」，而是「这次不换，但经验要吐一半」，防止玩家反复刷候选。

当前项目已有：三选一面板、放弃本次进化（计入 `放弃转职次数`）、永久不再进化、30 秒超时自动选第一个（[转职.lua:807-859](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E8%BD%AC%E8%81%8C.lua#L807-L859)）。**缺**：重随；取消有代价的返还语义；可随时切换的「自动/手动进化」开关。

### 2.4 执行层：整体替换 vs 差量迁移

源项目执行（[单位进化.lua:182-209](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）：

```lua
hero:add_hero_level(1, true)          -- 先升级
skill:notify("on_change_talent", hero_base.talentskill, hero_name)  -- 换天赋
hero:issue_order("stop")
hero:transformat(hero_name)           -- 引擎整体替换单位
table.insert(player.使用过的英雄, hero_name)
hero:notify("单位-完成进化", hero)     -- 解除状态锁
```

优点：引擎级替换，模型/属性/技能一次到位，不会漏字段。
缺点：依赖 `transformat` 保留物品/等级/状态的能力；自研框架没有等价 API 时不适用。

当前项目用**差量迁移**（[转职.lua:264-291](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E8%BD%AC%E8%81%8C.lua#L264-L291)）：新旧职业基础值逐项相减，用 `+= / -=` 叠加，再换模型/名称/图标/头像/弹道/技能。优势是等级、物品、天赋、增幅修正全部保留，且不依赖引擎替换；代价是新增职业字段时必须同步维护 `baseOf()`。

**结论**：当前方案更适合本项目，保持不动。

### 2.5 保护层：`状态:进化` 输入锁

源项目在开面板前给英雄加 Buff（[状态/进化.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E7%8A%B6%E6%80%81/%E8%BF%9B%E5%8C%96.lua)），一次性挂 6 条限制：

`晕眩 / 沉默 / 缴械 / 懒惰 / 破隐 / 无敌`

并在 `单位-完成进化` 事件里移除，`keep = true` 保证跨替换不丢。

这解决三个实际问题：
1. 面板打开期间玩家仍能右键走位、放技能 → 英雄跑到怪堆里；
2. 换模型的瞬间暴毙；
3. 进化流程与施法/攻击动画穿插导致动作错乱。

当前项目**没有这层保护**：`jobFlow.start` 只设 `转职流程中` 标记，英雄仍可行动（[转职.lua:887-935](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E8%BD%AC%E8%81%8C.lua#L887-L935)）。

## 3. 英雄属性体系

### 3.1 三围 → 派生链路

源项目把属性拆成五层：`基础X / 额外X / X加成% / X效果 / X提升`，再向上汇总（[三维属性.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/config/%E5%8D%95%E4%BD%8D%E5%B1%9E%E6%80%A7/%E4%B8%89%E7%BB%B4%E5%B1%9E%E6%80%A7.lua)）：

| 属性 | 默认系数 | 作用 |
|---|---|---|
| 力量提升 | 10 | 每点力量 → 生命 |
| 敏捷提升 | 0.1 | 每点敏捷 → 攻击恢复 |
| 智力提升 | 0.75 | 每点智力 → 技能伤害 |
| 主要属性提升 | 0.5 | 每点主属性 → 基础攻击 |

链路（以力量为例）：

```
基础力量 --(×力量加成%)--> 额外力量
基础力量 + 额外力量 --> 力量效果
力量效果 --(×力量提升 10)--> 基础生命
主属性（力量/敏捷/智力） --(×主要属性提升 0.5)--> 基础攻击
```

设计要点：
- **加成% 只作用于基础值**（`额外力量 += 基础力量 × 力量加成%`），不会自我复利；
- **主属性**由 `ref_attribute()` 在换职业后重算（[三维属性.lua:249-256](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/config/%E5%8D%95%E4%BD%8D%E5%B1%9E%E6%80%A7/%E4%B8%89%E7%BB%B4%E5%B1%9E%E6%80%A7.lua)），这是「换职业不丢属性」的关键；
- 全属性加法是 `基础全属性 → 三项基础`、`全属性加成% → 三项加成%` 的扇出（[三维属性.lua:181-207](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/config/%E5%8D%95%E4%BD%8D%E5%B1%9E%E6%80%A7/%E4%B8%89%E7%BB%B4%E5%B1%9E%E6%80%A7.lua)）。

当前项目框架已有 `str/agi/int` 与 `primary`，但没有 `加成% / 效果 / 提升` 这层中转，也没有「主属性重算」的显式入口。

### 3.2 成长属性：每级叠加

源项目 [成长属性.lua:43-80](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/config/%E5%8D%95%E4%BD%8D%E5%B1%9E%E6%80%A7/%E6%88%90%E9%95%BF%E5%B1%9E%E6%80%A7.lua)：

```lua
hero:add("基础生命", hero:get("生命成长") * level)
hero:add("基础攻击", hero:get("攻击成长") * level)
hero:add("基础护甲", hero:get("护甲成长") * level)
hero:add("基础力量", hero:get("力量成长") * level)
hero:add("基础智力", hero:get("智力成长") * level)
hero:add("基础敏捷", hero:get("敏捷成长") * level)
hero:add("基础全属性", hero:get("全属性成长") * level)
```

注意是 `成长值 × level` 而非 `成长值 × 1`，即**每级收益递增**（10 级时一次 +10 倍成长），配合 3.3 的增幅会指数化。

当前项目有杀敌经验与升级，但英雄基础数值主要来自职业模板，没有「成长属性」这一层。

### 3.3 进化增幅：滚雪球

紧接着升级回调里再按当前基础值加成（[成长属性.lua:62-78](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/config/%E5%8D%95%E4%BD%8D%E5%B1%9E%E6%80%A7/%E6%88%90%E9%95%BF%E5%B1%9E%E6%80%A7.lua)）：

```lua
hero:add("基础力量", str * hero:get("进化力量增幅") * 0.01)
hero:add("基础生命", hp  * hero:get("进化生命增幅") * 0.01)
...（攻击 / 护甲 / 三围 / 全属性 各一项）
```

即：**本次升级获得的成长，会成为下一次增幅的基数**。这是典型的正反馈曲线，适合长局（30 级上限），但需要严格控制增幅来源与上限，否则后期数值失控。

风险点：
- 增幅按「当前基础值」计算，若增幅属性本身可叠加，会变成复利；
- 与 `力量加成%` 等百分比属性叠加时，先后顺序会影响最终值（源项目靠 `on_set` 链式排队保证顺序）。

### 3.4 熟练度：跨局成长

[英雄熟练度.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E7%95%8C%E9%9D%A2/%E8%8B%B1%E9%9B%84%E5%9B%BE%E9%89%B4/%E8%8B%B1%E9%9B%84%E7%86%9F%E7%BB%83%E5%BA%A6.lua)：

| 项 | 值 |
|---|---|
| 存储 | `player:get_stored_integer(英雄名)`（跨局存档） |
| 等级阈值 | `1000 / 3500 / 8500 / 16000 / 26000`（5 级） |
| N 档奖励 | 基础攻击 +15、基础生命 +300、力/敏/智加成 +0.5% |
| R 档奖励 | +20 / +400 / 1% |
| SR 档奖励 | +25 / +500 / 1.5% |
| SSR 档奖励 | +30 / +600、法术伤害 +0.5%、物理伤害 +0.5%、最终伤害 +0.5% |

应用时机：`玩家-注册英雄` 时，遍历 73 个英雄，按已达成等级把奖励加到英雄/玩家（[英雄熟练度.lua:127-162](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E7%95%8C%E9%9D%A2/%E8%8B%B1%E9%9B%84%E5%9B%BE%E9%89%B4/%E8%8B%B1%E9%9B%84%E7%86%9F%E7%BB%83%E5%BA%A6.lua)）。

设计价值：
- 把「图鉴收集」从展示变成**数值回报**；
- 老玩家用熟英雄天然更强，降低换英雄的心理成本；
- 奖励按档位区分，天然与 2.2 的稀有度分层呼应。

当前项目已有图鉴卡片与羁绊存档（[存档.lua:136-140](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/setup/%E5%AD%98%E6%A1%A3.lua#L136-L140)），但没有「每个职业的熟练度成长」。

## 4. 技能与天赋体系

### 4.1 技能组织：复合体

每个英雄对应一个 `英雄技能[i]`，内部同时包含主动与被动：

```lua
ac.skill("英雄技能[43]")({ on_add, on_cast, on_remove })   -- 主动：开 Buff
ac.buff("效果:英雄技能[43]")({ ... })                      -- 被动：改攻击范围 / 伤害逻辑
```

见 [英雄技能[43].lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%8A%80%E8%83%BD/%E8%8B%B1%E9%9B%84%E6%8A%80%E8%83%BD/ssr%E7%BA%A7%E8%8B%B1%E9%9B%84/%E8%8B%B1%E9%9B%84%E6%8A%80%E8%83%BD%5B43%5D.lua)。简单被动技能则直接在 `on_add` 加属性、`on_remove` 扣回（[英雄技能[1].lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%8A%80%E8%83%BD/%E8%8B%B1%E9%9B%84%E6%8A%80%E8%83%BD/n%E7%BA%A7%E8%8B%B1%E9%9B%84/%E8%8B%B1%E9%9B%84%E6%8A%80%E8%83%BD%5B1%5D.lua)）。

编号即索引：N 1-14 / R 15-28 / SR 29-42 / SSR 43-73，**英雄与技能靠编号隐式对应**。这是内容量大的团队写法，但对 42 职业的当前项目来说，显式的 `skills = {...}` 更清晰。

### 4.2 天赋槽：`天赋显示[1..4]`

关键设计（[天赋显示.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%8A%80%E8%83%BD/%E8%8B%B1%E9%9B%84%E5%A4%A9%E8%B5%8B/%E5%A4%A9%E8%B5%8B%E6%98%BE%E7%A4%BA.lua)）：

- 英雄身上固定挂 4 个**展示槽**，槽本身不换；
- 槽内动态挂载真正的天赋技能 `unit:add_skill(talents, { parent = self })`；
- 进化时只调 `on_change_talent(新英雄天赋, 新英雄名)`，换掉槽内技能并同步图标/描述/冷却；
- `hero_name` 记录该槽绑定的英雄，用于 2.2 的候选排除（避免拿到同一套天赋）。

对比当前项目：天赋是**独立 Roguelike 三选一**（`TALENT_DEFS` + 刷新点 3，[天赋.lua:45](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/ability/%E5%A4%A9%E8%B5%8B.lua#L45)），与职业无关。

**评价**：两套设计服务不同目标——
- 源项目：天赋是**英雄身份的一部分**，换英雄=换玩法；
- 当前项目：天赋是**局内 Build 的一部分**，换职业不影响 Build。

当前项目的更符合 roguelike 割草品类的成长爽感，**不建议改成英雄绑定**；若要借鉴，只建议「给部分职业加专属天赋池」作为 P2 可选项，且保留现有通用池。

### 4.3 奥义 / 升华：占位槽 → 多选一

- 英雄注册时挂 `奥义技能[0]` / `升华技能[0]` 作为**占位**（[英雄配置.lua:58-77](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E9%85%8D%E7%BD%AE/%E8%8B%B1%E9%9B%84%E9%85%8D%E7%BD%AE.lua)）；
- 解锁事件 `玩家-解锁奥义技能` → 遍历 `奥义技能[1..6]` 组装选项 → 面板选择 → 移除占位、`add_skill` 真技能（[奥义技能.lua:29-62](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%A5%A5%E4%B9%89%E6%8A%80%E8%83%BD.lua)）；

当前项目奥义已是「第 5 次进化后 H 槽 5 选 1」，支持 30 秒兜底与失败重试（[转职.lua:581-740](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E8%BD%AC%E8%81%8C.lua#L581-L740)），**已优于源项目**（源项目此流程未做超时/重试兜底）。无需借鉴。

### 4.4 技能数值分档

同一套技能实现，按档位放大参数。例如：

| 项 | N 档 | SSR 档 | 差异 |
|---|---|---|---|
| 熟练度基础攻击 | +15 | +30 | 2 倍 |
| 熟练度生命 | +300 | +600 | 2 倍 |
| 天赋 62「支配死灵」 | 复用 `状态:英雄技能[62]` + `效果:英雄技能[63]` | 同结构，数值由技能字段驱动 | 共用战斗管道 |

即**技能是模板，数值是参数**：`power1 / increase / area / delay` 等字段决定强度，天赋与英雄技能共用同一套 Buff/伤害管道（[天赋技能[62].lua:1-53](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E7%94%9F%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%8A%80%E8%83%BD/%E8%8B%B1%E9%9B%84%E5%A4%A9%E8%B5%8B/ssr%E7%BA%A7%E8%8B%B1%E9%9B%84/%E5%A4%A9%E8%B5%8B%E6%8A%80%E8%83%BD%5B62%5D.lua)）。当前项目 42 职业的技能已各自独立实现（[tpl/ability/职业](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/ability/%E8%81%8C%E4%B8%9A)），若要引入分层，只需给职业打档位标签，不必重写技能。

- **可直接复用的先例**：天赋三选一面板已有「刷新点 + 杀敌数兜底刷新」的完整实现（`REFRESH_KEY = 天赋刷新点`，首次投放 `talent_refresh_points = 3`，[天赋.lua:1495-1497](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/ability/%E5%A4%A9%E8%B5%8B.lua#L1495-L1497)；点完可花 `talent_refresh_kill_cost = 200` 杀敌刷新，[天赋.lua:1456-1458](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/ability/%E5%A4%A9%E8%B5%8B.lua#L1456-L1458)），转职重随照此模型做即可，不必另造货币。
- **要点**：次数来源可以是「每局固定 2 次」或「杀敌奖励」；重抽必须重置超时计时器（沿用 `转职超时token`）。
- **风险**：重抽与「保留技能」选择状态需要一起重置；面板需回传当前已选技能槽。

### P0-2 进化状态锁

- **源实现**：`状态:进化` Buff，挂 `晕眩/沉默/缴械/懒惰/破隐/无敌`，`单位-完成进化` 时移除（[状态/进化.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E7%8A%B6%E6%80%81/%E8%BF%9B%E5%8C%96.lua)）。
- **落点**：`jobFlow.start` 设 `转职流程中` 时同时给英雄加限制；`jobFlow.change` 成功、`abandonFlow`、超时兜底三条路径都要解。
- **要点**：必须用「流程标记 → 限制」的一一对应，避免放弃后仍被锁。
- **风险**：无敌会屏蔽 BOSS 的机制伤害，需确认无敌只用于防暴毙而非免伤；源项目用 `破隐` 是防止面板期间被隐身单位偷袭。

### P0-3 手动/自动进化开关 + 取消代价

- **源实现**：`设置:手动进化` 可随时切换；取消进化扣一半当前经验（[单位进化.lua:214-225](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）。
- **落点**：当前项目已有 `不再转职` 与 `放弃转职次数`，可扩展为三态 `进化模式 = 自动 / 手动 / 关闭`；取消时按「本次门槛的一半」回退 `放弃转职次数` 或给予补偿。
- **要点**：回退必须与 `getEvolveProgress` 的口径一致（当前用 `totalKill` 减历次需求，见 [刷怪.lua:313-326](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E5%88%B7%E6%80%AA.lua#L313-L326)）。
- **风险**：`totalKill` 与 `kill` 分离，回退操作不能直接改 `totalKill`，否则会与战功商店消费冲突。

### P1-1 职业稀有度分层 + 加权池

- **源实现**：两层权重池 + 可成长权重属性（[单位进化.lua:1-100](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E5%AD%98/map/scripts/%E5%9C%B0%E5%9B%BE/%E6%B5%81%E7%A8%8B/%E6%B8%B8%E6%88%8F%E7%B3%BB%E7%BB%9F/%E5%8D%95%E4%BD%8D%E8%BF%9B%E5%8C%96.lua)）。
- **落点**：[game.lua:114](file:///d:/Lua/xlik-jade/projects/demo/library/common/game.lua#L114) 的 `game.config.jobs` 每条加 `tier = 'N'|'R'|'SR'|'SSR'`；新增 `game.config.job_tier_weight = { N=70, R=22, SR=6, SSR=2 }`；把 `roll()` 改成分层加权抽取。
- **要点**：42 职业按强度/机制复杂度打标；候选 3 个可以在同一档位内去重；保底规则简化为「连续 N 次未出 SR+ 则下一次必出」的软保底，比 VIP 门槛更适合单机割草。
- **风险**：现有 42 职业基础数值跨度大（hp 100~3500、attack 10~20）且与技能强度不严格对应，分层后需要同步调整强度预期，否则「SSR」名不副实。

### P1-2 图鉴熟练度（跨局成长）

- **源实现**：每英雄存档整数，5 级阈值，按档位给固定加成（[英雄熟练度.lua](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E5%AD%98/map/scripts/%E7%95%8C%E9%9D%A2/%E8%8B%B1%E9%9B%84%E5%9B%BE%E9%89%B4/%E8%8B%B1%E9%9B%84%E7%86%9F%E7%BB%83%E5%BA%A6.lua)）。
- **落点**：[存档.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/setup/%E5%AD%98%E6%A1%A3.lua) 新增 `FIELD['职业熟练度']`（42 个职业 → 数值）；选职业/转职成功时累加；应用时机参考源项目「注册英雄时套加成」，当前项目可在 `jobFlow.change` 后结算。
- **要点**：熟练度获取量可与杀敌数挂钩（如每 1000 杀 +1），阈值按单局时长（约 30 分钟）标定，建议 `{500, 1500, 3000, 6000, 10000}` 量级（需实测）。
- **风险**：跨局成长会拉大新老玩家差距，需给加成设上限（例如每职业最多 +10% 主属性）。

### P2-1 成长 / 进化增幅属性

- **源实现**：成长属性 `× level` 叠加 + 进化增幅按基础值百分比再乘（[成长属性.lua:43-86](file:///D:/Lua/%E4%B8%8D%E6%80%9D%E8%AE%AE%E5%AD%98/map/scripts/config/%E5%8D%95%E4%BD%8D%E5%B1%9E%E6%80%A7/%E6%88%90%E9%95%BF%E5%B1%9E%E6%80%A7.lua)）。
- **落点**：当前项目的英雄升级回调（`英雄-提升等级` 等价事件）里补一层属性成长；职业数据加可选 `growth = { hp=..., attack=... }`。
- **要点**：先做「线性成长」，不要一开始就上「进化增幅」复利；复利需要上限保护（如每项最多 +100%）。
- **风险**：当前项目的怪物数值是分波次硬编码表（[刷怪.lua:64-98](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E5%88%B7%E6%80%AA.lua#L64-L98)），英雄成长曲线一旦变化，怪物表需要重新标定。

### P2-2 技能复合体 / 天赋槽

- **源实现**：`英雄技能[i]` = 主动 + 被动 Buff；`天赋显示[1..4]` 动态挂载。
- **落点**：当前项目职业技能已是独立 AbilityTpl，**无需改造**；仅当未来要做「职业专属天赋」时，可借鉴「固定展示槽 + 内部动态技能」的结构。
- **风险**：会与现有 Roguelike 天赋池冲突，需明确二者边界。

## 7. 不建议照搬

| 项 | 原因 |
|---|---|
| `hero:transformat()` 整体替换 | 依赖引擎替换 API，当前框架用差量迁移更稳，且能保留物品/天赋/增幅 |
| 73 英雄 × 四档目录 | 内容维护成本高；当前 42 职业用「标签 + 权重」即可表达分层 |
| `disable_list` 位掩码 | 可读性差、易错；建议显式 `{ disabled = { '职业A', '职业B' } }` |
| `效果-英雄技能[3]` 隐式 SSR 分支 | 用 Buff 存在性控制池子，维护者难以发现；应改为显式配置或玩家状态字段 |
| 天赋与英雄强绑定 | 与当前 Roguelike 天赋路线冲突，会削弱局内 Build 乐趣 |

## 9. 后续修改点（已确认保留，本次不实施）

以下两项经确认保留，作为后续迭代的固定待办，实施时直接按本节的落点改造。

### 后续-1（原 P0-1）候选重随

- **目标**：进化面板支持「重新随机」，把纯随机变成可管理的随机，降低被低质量候选锁死的挫败。
- **落点**：
  - 面板 `xlik_job` 增加「重随」按钮与剩余次数显示；
  - 新同步事件 `xlik_job_reroll` → [转职.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E8%BD%AC%E8%81%8C.lua) 新增 `jobFlow.reroll(pla)`；
  - 次数模型复用天赋面板先例：固定次数 + 杀敌兜底刷新（`天赋刷新点` / `talent_refresh_kill_cost`）；
  - 重抽结果需排除当前已展示的候选，并重置 `转职超时token`。
- **验收**：面板可重随、次数正确扣减、超时不误触发、重随后「保留技能」选择状态被重置。

### 后续-2（原 P1-2）图鉴熟练度（跨局成长）

- **目标**：复用现有图鉴/存档，做「玩得多就变强」的长期留存。
- **落点**：
  - [存档.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/setup/%E5%AD%98%E6%A1%A3.lua) 新增 `FIELD['职业熟练度']`（职业名 → 数值）；
  - 转职成功（`jobFlow.change`）时累加，量级与杀敌数挂钩；
  - 阈值建议 `{500, 1500, 3000, 6000, 10000}`，每级给固定加成（主属性/生命）；
  - 加成应用时机对齐「注册/转职时套加成」，并设上限避免新老玩家差距过大。
- **验收**：跨局数值可持久化、按阈值正确升级、加成只生效一次且可读。
