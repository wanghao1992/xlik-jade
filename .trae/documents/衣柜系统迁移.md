# 衣柜系统迁移（老图 死灵狂潮 → xlik-jade demo）

## 一、目标与范围

把老图 [内容/衣柜](file:///d:/Lua/%E6%AD%BB%E7%81%B5%E7%8B%82%E6%BD%AE/map/scripts/maps/%E5%86%85%E5%AE%B9/%E8%A1%A3%E6%9F%9C) 整套搬进 demo：

- **6 类装扮**（`光环 / 称号 / 武器 / 翅膀 / 周身 / 皮肤`），**全量条目**照搬（老图 `数据.lua` 中未被注释的条目，约 166 条）。
- **面板**（新套件 `xlik_wardrobe`）：类型横排按钮 + 卡片网格分页 + 未解锁蒙版 + 已穿戴高亮 + 悬停说明 + 「一键脱下」+「关闭」。
- **穿戴/卸下**：服务端权威；穿戴即生效（附着特效 / 换模型+颜色+缩放+高度），同类型互斥；卸下恢复原状。
- **持久化**：照搬老图存档键 `衣柜` 组（平台 key `k12`，布尔位图，槽位 = 装扮 `id`），重开游戏/新建英雄自动重穿（穿戴记录 + 解锁条件双判定）。
- **资源迁移**：从 `d:\Lua\死灵狂潮\resource` 拷贝装扮的模型（mdx）、图标（blp/tga）、边框/蒙版（tga），并把模型内贴图引用改写到 `war3mapTextures\`。
- **入口**：功能栏「衣柜(P)」（当前是 `print` 占位）。
- **与签到闭环**：老图部分装扮（希瓦光环=第1轮满签；4 款皮肤=第3~6轮满签）的解锁条件就是"签到满 7 天"，本项目签到系统已迁移完成 → 衣柜直接消费 `qiandaoFlow.daySum(player, 轮次)`；同时把 [签到流程.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E7%AD%BE%E5%88%B0%E6%B5%81%E7%A8%8B.lua#L65-L74) 第 7 天文案里"（待衣柜系统接入）"改掉。

**条件处理（已确认：全量条目 + 不可用项占位）**：

- demo 有等价条件的条目 → 正常可解锁（映射表见 §3.3、附录 A）。
- 依赖**商城购买 / 活动抽奖 / 通行证 / 大圣碎片 / 新春积分(XC) / 粉8 / 鬼谷子+神曲** 等 demo 不存在来源的条目 → **保留在面板里**，条件恒为 `false`，数据上加 `unavailable = true`，tips 里追加一行"（demo 未实现该来源，暂不可解锁）"并保留老图原文需求文案。

**明确不做**：

- 老图 [衣柜/定制](file:///d:/Lua/%E6%AD%BB%E7%81%B5%E7%8B%82%E6%BD%AE/map/scripts/maps/%E5%86%85%E5%AE%B9/%E8%A1%A3%E6%9F%9C/%E5%AE%9A%E5%88%B6)（按玩家名/赞助者绑定的定制皮肤）——该目录下两个文件在磁盘上是**空文件**（0 行），无内容可迁。
- 老图 `宝库` 里的"装扮类型列表"（[宝库/数据.lua:362](file:///d:/Lua/%E6%AD%BB%E7%81%B5%E7%8B%82%E6%BD%AE/map/scripts/maps/%E5%86%85%E5%AE%B9/%E5%AE%9D%E5%BA%93/%E6%95%B0%E6%8D%AE.lua#L362)）——那是宝库（抽奖）系统，demo 无宝库；本次只做衣柜。

## 三、改造方案

### 3.1 存储：[存档.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/setup/%E5%AD%98%E6%A1%A3.lua#L122-L124) 新增「衣柜」布尔组

紧随现有 `FIELD['签到']` 之后追加：

```lua
--- 衣柜组(照搬老图 server_value_type.lua:310-317: key 'k12', 布尔值)
--- 每 key 60 字符 × 6 位 = 360 个位, 槽位 = 装扮 id(true = 当前穿着)
FIELD['衣柜'] = { type = 'bool', keys = { 'k12' } }
```

约束：装扮 `id` 必须 ≤ 360（老图数据里最大 id 为三位数以下，实测无 ≥300 的 id）；数据加载时对 `id > 360` 的条目打印告警并跳过穿戴（不写入存档）。

### 3.2 资源迁移（一次性脚本 + 目录布局）

资源来源：`d:\Lua\死灵狂潮\resource\`（根目录 + `商城\`、`积分\`、`新春活动\`、`宝库\` 等子目录）。

**目标布局**：

| 资源 | 目标目录 | 声明 |
|---|---|---|
| 装扮模型 mdx | `vendor/assets/war3mapModel/wardrobe/<原文件名>` | `assets_model("wardrobe/<原名>", "<别称>")`，别称 = 去扩展名的文件名（如 `紫宇光环`） |
| 模型贴图 blp | `vendor/assets/war3mapTextures/<文件名>` | 无需声明（工具按模型内引用自动引入） |
| 图标 blp/tga（老图 `art`） | `vendor/assets/war3mapImage/<老图相对路径>`（保留 `商城/`、`积分/`、`新春活动/` 等子目录与根目录文件） | `assets_image("商城/紫宇光环.blp")` 等，路径用正斜杠 |
| 边框/蒙版 tga | `vendor/assets/war3mapImage/`（根） | `assets_image("通用边框.tga")`、`assets_image("存档禁用蒙版.tga")`、`assets_image(string.format("边框_lv%d.tga", i))`（i=1..8） |

**一次性迁移脚本**（临时工具，放 `.trae/tmp/migrate_wardrobe.lua`，跑完即删，不进交付代码）：

1. 读老图 `数据.lua`，提取全部非注释的 `model` / `art` / `边框文件` 引用集合（正则按行提取即可，格式高度规整）。
2. 模型：在 `死灵狂潮/resource` 递归按文件名查找 → 拷贝到 `war3mapModel/wardrobe/`；找不到的记入**模型缺失清单**（如 `大圣皮肤新 (2)`，磁盘无同名文件）。
3. **模型贴图路径改写**（关键）：
   - 模型内 `.blp` 引用分三类：内置（`Textures\`、`ReplaceableTextures\`、`UI\`、`Units\`/`units\` 前缀）→ 不动；自定义（`war3mapImported\X.blp` 或裸名 `X.blp`）→ 若能在 `死灵狂潮/resource` 找到同名文件，则拷到 `war3mapTextures/` 并把模型内路径改写为 `war3mapTextures\X.blp`；找不到且非内置 → 记入**贴图缺失清单**。
   - 改写实现：MDX 的 `TEXS` chunk 中每个贴图条目为**定长记录**（`replaceableId(4) + path(260, 以 \0 填充) + flags(4)`），因此只需等长覆盖 path 字段（新路径 + `\0` 补齐），**无需修改 chunk size**，二进制安全。
   - 验证方式：`xlik.exe run demo -l!` 的输出中 `【模型】Textures 引入：N张` 应等于拷入 `war3mapTextures` 且被引用的数量，且**不得出现** `【模型】Textures： X 不存在`（该报错来自 [luaAssets.go:531-544](file:///d:/Lua/xlik-jade/exe/lib/luaAssets.go#L531-L544)）。
4. 图标/边框/蒙版：按老图 `art` 相对路径（`\` → `/`）与根目录文件名拷贝到 `war3mapImage/` 对应位置；`ReplaceableTextures\...` 这类魔兽内置图标**不拷**，代码里直接用原路径。
5. 脚本最后打印三份清单：**已拷贝模型数 / 已拷贝贴图数 / 已拷贝图标数**、**模型缺失清单**、**贴图缺失清单**。缺失项在数据文件里以注释标注，装扮本身保留（属性照常生效，仅外观不完整或退化为默认模型）。

**实测抽样**（已用脚本验证，作为可行性依据）：`紫宇光环.mdx` 只引用内置贴图；`能量光环.mdx` 引用的 `AZ_Rune7/AZ_glow1/AZ_glow3/AZ_bat2_4x4/AZ_Shockwave24/31` 与 `神秘光环` 等自定义贴图**在 resource 里存在**；`极致之翼.mdx`（`war3mapImported\dtcb011.blp`）、`炫彩光剑.mdx`（`war3mapImported\Tex_0418_0.blp`）的贴图**磁盘缺失**（只在老图编译包里）——这类就是"贴图缺失清单"的内容，模型仍可加载（缺失贴图部位显示异常）。

### 3.3 数据文件：新增 `projects/demo/scripts/globals/setup/衣柜.lua`（全局 `wardrobeData`）
