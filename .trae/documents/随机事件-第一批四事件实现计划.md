# 随机事件：第一批四事件实现计划

> 依据《游戏玩家灵感收录.md》，采用「分批推进」方案，本批实现**依赖较少**的四个事件：
> **天罚惩戒（忽略惩罚）**、**血泉倒转（泉水反转）**、**九转重元（散功重修）**、**限时追捕（逃跑怪）**。
> 位移/击飞/UI投票类（天降巨剑、精准收割、坐骑冲锋、分身诱饵、窃金之手、吸星大法）留作后续批次。
> 本批不新增任何 UI 套件、不引入击飞等新基建，全部复用现有框架设施。

## 一、总目标

把文档中已完全确定（「待验证/疑问：暂无」）的 4 个随机事件接入现有随机事件池，
复用现有触发链路（杀敌达标 → `randomEvent.rollOne` → 弹出 → 接受 `apply` / 忽略）。
各事件数据追加到 `随机事件数据.lua`，忽略分支的「天罚惩戒」在 `随机事件.lua` 的忽略回调内实现。

## 三、通用基建（本批新增、可复用）

### 3.1 `game.method.pctHpDamage(target, pct, source)` —— 按最大生命扣真实伤害
- 目的：天罚落雷（10% 最大生命）、血泉玩家掉血（10% 最大生命）共用；走 `ability.damage` → 默认被**无敌免疫**、命中死亡走**假死/自动复活**流程（与现存 `damaging.lua` 口径一致）。
- 位置：`随机事件.lua`（与 `eventAttr` 同文件），导出为 `game.method.pctHpDamage`。
- 参数：目标、百分比（0.1=10%）、可选来源单位；`damageSrc=injury.damageSrc.ability`，`damageType=injury.damageType.magic`。
- 实现：`ability.damage({sourceUnit=source or hero, targetUnit=target, damage=math.ceil((target:hp() or 1)*pct), ...})`。

### 3.2 天罚的「预警圈 + 延迟落雷」演出
- 复用 `job.telegraph({model='圆形预警', x, y, radius=200, delay=1})`（已有"先出圈→延迟落地动画"节拍，见 [职业工具.lua#L298](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/setup/职业工具.lua#L298) 与 BOSS 魔君口径）。
- 支持按位置出圈：天罚每 tick 记录**此刻英雄位置 P0** → 在 P0 出 200 码预警圈（预警 1s）→ 1s 后 P0 落雷特效 + 结算伤害。
- 落雷视觉：用一个 War3 原生雷击/落雷点特效模型（实现时在 `BOSS技能.lua`/`职业工具.lua` 已用模型里挑一只，如冲击+雷击组合）。

## 四、事件 1：天罚惩戒（忽略惩罚）

**归属**：非独立随机事件，是「忽略」的后果分支。
**触发点**：`随机事件.lua` 的 `sync.receive('xlik_event_ignore', ...)`，在清空 `pending` 并 `close` 之后。

**要点（文档原文锁定）**
- 忽略后有 **50% 几率**触发（每次忽略独立判定），给玩家挂一个 **30 秒** debuff。
- 每秒在**玩家当前所在位置**生成 200 码预警圈（预警时长 1s）。
- 预警结束后在**预警圈生成时的位置**（非落雷瞬间位置）降下神雷（200 码）。
- 被神雷击中：扣 **10% 最大生命**（`pctHpDamage`），并有 **50% 几率被眩晕 0.5 秒**（每次独立掷骰，`ability.stun`）。
- 该 debuff **不可驱散**；**无敌状态可免疫伤害**（落雷命中结算由 `ability.damage` 天然免疫无敌）。
- 落雷可打死玩家 → 正常「假死」流程 + 若可复活自动复活（现有系统兜底）。

**实现方案（随机事件.lua）**
- 新增 `randomEvent.ignorePunish(pla, hero)`：
  - 若同英雄已有天罚进行中（标记 `hero._punishActive`）则**刷新/不重复**，直接返回（防叠加刷落雷）。
  - 置标记；`time.setInterval(1, ...)` 每秒：
    - 记录 `P0 = hero:x(), hero:y()`（需 `class.isObject(hero,UnitClass)` 且未死，否则跳过本次 tick）。
    - `job.telegraph(预警圈, P0, 200, delay=1)`。
    - `time.setTimeout(1, ...)` 后在 **P0**：落雷特效 + `pctHpDamage(hero, 0.1, hero)` + `50% → ability.stun({targetUnit=hero, sourceUnit=hero, duration=0.5})`（眩晕对无敌目标由 damage/stun 防御端天然处理）。
  - `time.setTimeout(30, ...)` 后清除标记、注销 interval。
- 在忽略回调末尾：`if (math.rand(1,100) <= 50) then randomEvent.ignorePunish(pla, hero) end`（英雄存在且未死时）。
- **不可驱散**：不依赖 Buff 驱散系统，用独立的 interval+timeout 实现 debuff，天然不可被驱散/清理，30s 到点自愈。
- **UI 提示**：触发时 `alerter.message(pla, '天罚惩戒：30秒内持续走位躲避落雷！')`。

**数据注册（随机事件数据.lua）**：本事件不进随机池，不放 `add()`；仅需在文档/规则层面说明（不改池）。因此**不占 `add({})` 名额、不配 rarity/icon**。

## 五、事件 2：血泉倒转（泉水反转）

**事件数据（随机事件数据.lua 追加 `add({...})`）**
- `name='血泉倒转'`，`rarity='rare'`，`weight=2`。
- `desc='生命之泉提前『失灵』：30秒内你靠近泉水改为掉血，而怪物靠近泉水会回血'`。
- `apply = function(self, pla, hero)`：调 `game.method.fountainFlip(true)`，`time.setTimeout(30, ...)` 后 `fountainFlip(false)`。`alerter` 播报。

**核心：改造 `生命之泉.lua`（[SOURCE](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/创建NPC/生命之泉.lua)）**
- 新增全局开关 `game.method.fountainReversed`（默认 `false`）与 setter `game.method.fountainFlip(flag)`。
- 每座泉水现有 `time.setInterval(1, ...)`（半径 500、10%/s 回血）改造为：
  - `targets = Group(...)`：半径 500 内、存活、非自身。
  - 未反转（正常）：维持现状——`isAlly(npc:owner())` 的**玩家英雄**回血 10%（`effector.attach(回复生命)`）。
  - 反转（30s）：拆成两分支：
    - **玩家英雄**在范围 → `pctHpDamage(hero, 0.1, npc)`（掉血；可致死走假死；无敌免疫）。
    - **怪物**（`mob:get('小怪')` 的小怪/事件怪，敌方）在范围 → 回血（数值 = `当前英雄的 hpRegen` 值，频率同 1s；`effector.attach(回复生命)` 表现）。
- **F3 挂机区不生效**：为「泉水是否受反转影响」提供开关/判断。实现方式二选一：
  - A：在 `createFountain` 加参数 `flip=true/false`，F3 那座传 `false`；其它传 `true`。
  - B：维护一张「F3 泉水坐标表」，判断当前泉水坐标不在 F3 区才反转。
  - **待确认**：F3 挂机区对应的泉水坐标/区域。默认先按「四边中点 1 座 + 四角 4 座共享反转，F3 区单独列为常量并在实现时确认坐标」处理（见「七、待确认」）。

**替换注意**：每座泉水的 interval 独立跑，反转开关用全局字段，各 interval 读同一布尔即可并发一致；30s 结束 `fountainFlip(false)` 自然恢复。

## 六、事件 3：九转重元（散功重修）

**事件数据（随机事件数据.lua 追加 `add({...})`）**
- `name='九转重元'`，`rarity='epic'`，`weight=1`。
- `desc='散尽全部修为：攻击/护甲/力量/敏捷/智力归1并锁定，无敌且缴械60秒；结束后修为回满并永久×1.5'`。
- `apply = function(self, pla, hero)`：见下。

**「修为」五维**：攻击力（`hero:attack`）、护甲（`hero:defend`）、力量（`hero:str`）、敏捷（`hero:agi`）、智力（`hero:int`）。

**实现方案（apply 内）**
1. **快照**：`local atk, def, s, a, i = hero:attack(), hero:defend(), hero:str(), hero:agi(), hero:int()`（`modify` 无参 getter 返回当前终值）。
2. **无敌 + 缴械（引用计数）**：`ability.invulnerable({whichUnit=hero, duration=60, name=..., icon=...})`、`ability.unArm({whichUnit=hero, duration=60, ...})` —— 二者内部用 `superposition.plus/minus` 引用计数，Buff 到期各自 `minus` 只解除本事件这一层，天然满足「只减 1、不解除其它来源」（与文档状态引用计数一致）。
3. **归 1 + 锁定（60s）**：`time.setInterval(0.25, ...)`：
   - 每 tick 对五项调用「终值→1」的补偿写回：`local amp = (hero:ampl('attack') or 0)` → `hero:attack('=' .. 1/(1+amp/100))`（把基础值设为「使得当刻终值≈1」的补偿值）；其余四维同理（str/agi/int/defend）。`_attr` 扁平加成若直接参与终值，按同样思路反推（实现时以实测为准，见注）。
   - 作用：其它来源的增减在 0.25s 内被压回 ≈1 → 满足「持续锁定为 1、不增不减」。
   - `time.setTimeout(60, ...)` 后注销 interval。
4. **结束恢复 ×1.5（永久）**：`hero:attack('=' .. atk*1.5)`、`hero:defend('=' .. def*1.5)`、`hero:str('=' .. s*1.5)`、`hero:agi('=' .. a*1.5)`、`hero:int('=' .. i*1.5)`。若期间无敌/缴械被事件提前解除，引用计数由 ability 自动兜底。
5. `alerter.message(pla, '散功结束！修为恢复并永久×1.5！')`。

> **注（终值=1 精度）**：`modify` 的 `get` 为「基础值 ×(1+ampl/100)+扁平`_attr`」的口径。为控制本批复杂度，锁定采用「按当刻 ampl 逆推基础值使终值≈1」的策略；`_attr` 扁平项在实现时若发现参与终值，则对对应键做同等逆推。由于执行者无法实机跑图，此精度项列为**实现后需用户实机校验**。

**适用沿用**：本事件走标准 `add()`/`apply`，触发、弹出、接受/忽略、天罚分支均不特殊。

## 七、事件 4：限时追捕（逃跑怪）

**事件数据（随机事件数据.lua 追加 `add({...})`）**
- `name='限时追捕'`，`rarity='rare'`，`weight=2`。
- `desc='一只打不死的怪随机出现！限时内命中它10次完成（奖励），超时轻微惩罚'`。
- `apply`：调 `随机事件.lua` 新增 `randomEvent.startHunt(pla, hero)`。

**实现方案（随机事件.lua + 数据表）**
- **限时**：定长 `huntTime`（默认 30s，实现时给 `pickByWave` 或固定值）。`time.setTimeout(结束, ...)` 结算。
- **生成逃跑怪**（复用 `game.method.spawnEventMob` 思路但特殊标记）：
  - 模板用 War3 原生移速快模型（实现时若复用 `bladeTpl/harpyTpl` 列表，避免与既有事件怪冲突，加唯一 `_eventTag`）。
  - **打不死**：置 `怪._hunt=true` 且 `ability`/属性使其伤势不致死——最简单用 `superposition.plus(怪,'invulnerable')` 使其不被伤害（攻击仍可用 `orderAttack` 造成"命中"）。命中事件用 `event.syncRegister(UnitClass, eventKind.unitHurt, ...)` 或攻击受击回调判定（实现时确认事件名，`eventKind` 里 `unitDead/unitHurt`）。
  - **受击即计数 + 瞬移**：每次「命中」→ 命中计数 +1（无需掉血）→ 触发一次瞬移；瞬移最小间隔 0.5s（0.5s 内多次命中只瞬移一次，避免高攻速失控）。
  - **瞬移落点**：在距玩家 **≥2500 码**的随机位置择位（不超地图边界、不卡障碍 → 用框架 `terrain`/地图尺寸裁切，失败重随若干次）。
- **命中 10 次** → 成功：注销监听与超时，`alerter.message` 给奖励（奖励内容沿用`pickByWave`金币/经验，或文档示例——实现时给金币+少量经验）。
- **超时未满 10 次** → 必给**轻微惩罚**（`pctHpDamage` 不适用；按文档：**扣少量金币 + 10 秒小幅减速**）：
  - 金币：`pla:worth('+',{gold=-n})`。
  - 减速：`hero:move('*=0.8')` + `time.setTimeout(10, 还原)`（或复用 `heroBuff` 移速类，见数据表现有 `heroBuff`）。无「无惩罚」选项。
- **UI 提示进度 + 倒计时**：优先用现有轻量手段（`alerter.message` 阶段性播报）；若需常驻进度条，本批先用「每次命中播报 X/10、倒计时 5s 提示一次」的聊天播报近似，**不新增 UI 套件**（后续批次若需可做）。
- 事件结束/成功/超时统一清理：注销监听、注销超时、`杀怪`（打不死的怪事件结束后 `mob:kill()` 收尾，避免残留）。

## 十、验证步骤

1. 静态：`luac -p` 校验 `随机事件数据.lua`、`随机事件.lua`、`生命之泉.lua`（本批全部改动文件）。
2. 实机（用户自行 `xlik.exe run demo -l!`，本代理不执行打包/跑图）：
   - 杀敌里程碑弹出池中含：血泉倒转、九转重元、限时追捕，各自可被抽取、接受生效、忽略走天罚分支。

   - **血泉倒转**：30s 内靠近泉水玩家掉血、怪物回血，到点恢复；F3 区（若有标记）不反转。
   - **九转重元**：accept 后五项归 1 + 无敌 + 缴械；60s 结束后五项恢复并永久 ×1.5；无敌/缴械引用计数正确（不误伤其它来源）。
   - **限时追捕**：逃跑怪打不死、受击瞬移、10 次命中成功得奖励；超时给轻微惩罚；结束后无残留。
3. 回归：`eventAttr` 属性口径、杀敌里程碑、`xlik_event` 套件打开/关闭不受影响。
