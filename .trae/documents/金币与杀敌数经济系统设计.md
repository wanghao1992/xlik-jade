# 金币与杀敌数经济系统设计（demo）

## 一、概要

### 1.1 问题

- 金币出口只有专属装备升级与重铸，总量约 **120 万**且全部一次性；而金币收入随击杀速度无限增长 → 满级后金币必然变成废纸。
- 杀敌数（`kill` / `totalKill`）只作为转职门槛、随机事件里程碑和界面进度，**没有任何消费出口**。

### 1.2 本次范围

| 编号 | 内容 | 是否本次实现 |
|---|---|---|
| P0-a | `kill` 改为可消费余额（`totalKill` 保持只增不减） | 是 |
| P0-b | 专属装备「词条洗练」：满 100 级后无限消耗金币 | 是 |
| P0-c | 「战功商店」：新 UI 套件 `xlik_shop` + 功能栏按钮 + 7 件商品 | 是 |
| P2 | 局末杀敌结算永久点、词条锁定（洗练时保留指定词条） | 否（预留） |

### 1.3 设计原则

1. **金币换数值、杀敌换机会**：金币收入随 DPS 无限涨，出口必须是不设硬上限、靠玩家自己反复投入的机制（洗练）；杀敌数只换有限次的“机会”（天赋点/刷新点/挑战次数/短时 BUFF）。
2. **不新增伤害乘区**：洗练只在既有 `AFFIX_DEFS` 数值表内重roll，品质封顶 5；商店数值商品全部限购。
3. **不新增 worth 资源键**：复用 `kill`，`totalKill` 不动。
4. **复用既有系统**：挑战门票接 `cornerChallenge`（四角挑战），BUFF 接 `Buff`/`job.attrBuff`，不新造第二套挑战/BUFF 框架。

--- 当前转职进度(已累计杀敌 - 历次转职需求, 下一次需求)
---@param player Player

local function getEvolveProgress(player)

## 四、专属装备词条洗练（P0-b）

### 4.1 规则

| 项 | 值 |
|---|---|
| 解锁 | **单件**装备等级达到 100（`levelMax`），且 4 条词条已齐（10/20/30/40 各一条） |
| 入口 | 物品「使用」= 洗练 1 次。**右键批量升级在满级时直接无效**（不批量洗练，避免误点烧钱） |
| 效果 | 重新随机 **全部 4 条词条**的「名称 + 品质 + 数值」；每条的 `upgrade`（强化次数）保留 |
| 成本 | 第 n 次洗练 = `floor(50000 × 1.10^(n-1))`，`n` 存 `it._equipSweep` |
| 上限 | 无硬上限。词条品质封顶 5、词条名取自 `def.affixPool`，不产生新乘区 |
| 持久化 | 运行时字段 `it._equipSweep`（与 `_equipMul` 同级，不写存档） |

**为什么是“整体重roll”而不是“只洗品质”或“单条洗”**：
- 只洗品质会在 4 条全 5 品质时彻底到顶，金币重新变成废纸；
- 整体重roll带“词条类型”随机，玩家可以反复赌更好的词条组合，天然是长期金币池；
- 单条洗需要“先选槽位再选候选”的两级交互，现有 `xlik_affix` 面板是“四选一追加”语义，改造面更大。

### 4.2 成本曲线

| 第 n 次 | 成本（金币） | 累计 |
|---|---|---|
| 1 | 50,000 | 50,000 |
| 5 | 73,205 | 约 30.5 万 |
| 10 | 117,897 | 约 79.7 万 |
| 15 | 189,872 | 约 158.9 万 |
| 20 | 305,794 | 约 286.4 万 |
| 25 | 492,472 | 约 491.7 万 |
| 30 | 793,148 | 约 822.5 万 |

按单局剩余金币 300 万~500 万估算，单局可洗练 **20~25 次**，恰好把满级后的余钱吸干；不会出现“一次洗练就烧光”或“钱多到没处洗”的两极。

**新增函数骨架**

```lua
--- 词条洗练: 解锁等级 / 基础金币 / 每次成本成长率
local SWEEP_LEVEL = 100
local SWEEP_BASE_GOLD = 50000
local SWEEP_GROWTH = 1.10

--- 洗练成本(随该装备累计洗练次数指数递增)
---@param it Item
---@return number
local function sweepCost(it)
    local n = it._equipSweep or 0
    return math.floor(SWEEP_BASE_GOLD * (SWEEP_GROWTH ^ n))
end

--- 重新随机 count 条互不重复的词条(名称+品质+数值)
---@param def table 装备数据
---@param count number
---@return table[] {name, quality, value}
local function rollSweepAffixes(def, count)
    local names = {}
    for _, name in ipairs(def.affixPool) do
        names[#names + 1] = name
    end
    local out = {}
    for i = 1, math.min(count, #names) do
        local name = table.remove(names, math.rand(1, #names))
        local affixDef = AFFIX_DEFS[name]
        local quality, value = rollQuality(affixDef)
        out[i] = { name = name, quality = quality, value = value }
    end
    return out
end

--- 洗练一次(满级后「使用」触发)
---@param pla Player
---@param it Item
---@param def table
---@return boolean
local function sweepOnce(pla, it, def)
    local olds = it._equipAffix or {}
    if (it:level() < SWEEP_LEVEL) then
        alerter.message(pla, "需要达到 " .. SWEEP_LEVEL .. " 级才能洗练词条")
        return false
    end
    if (#olds < 4) then
        alerter.message(pla, "词条未集齐，暂不能洗练")
        return false
    end
    local cost = sweepCost(it)
    if ((pla:worth()["gold"] or 0) < cost) then
        alerter.message(pla, "金币不足，洗练需要 " .. cost .. " 金币")
        return false
    end
    pla:worth("-", { gold = cost })
    --- 强化次数按槽位保留(40级后每10级强化1条, 换名后仍挂在原位)
    local news = rollSweepAffixes(def, 4)
    for i = 1, 4 do
        if (nil ~= news[i]) then
            news[i].upgrade = olds[i] and (olds[i].upgrade or 0) or 0
        end
    end
    it._equipAffix = news
    it._equipSweep = (it._equipSweep or 0) + 1
    local hero = it:bindUnit()
    if (true == it._equipOn and class.isObject(hero, UnitClass)) then
        equipRefresh(it, def, hero)
    end
    local txt = {}
    for i = 1, 4 do
        txt[i] = affixText(news[i])
    end
    alerter.message(pla, ("洗练完成(%d 金币): %s"):format(cost, table.concat(txt, " / ")))
    return true
end
```

### 4.4 一致性校验点

- `equipRefresh` 用 `cur.source` 回退旧词条、用新 `source` 生效（[L510-515](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/item/专属装备.lua#L510-L515)），换名换 kind/keys 都不会把数值扣到不相干属性上。

- 重铸倍率 `_equipMul` 照常乘在 `want` 上，洗练不改变倍率，两者互不干扰。
- 右键批量升级在满级时第一次 `upgradeOnce` 即返回 false 并 `break`，不会连带洗练。

`buy` 的强制校验顺序（`worth` 会把负数夹到 0，不能依赖它兜底）：

1. 玩家 / 英雄有效；
2. 商品存在；
3. `owned < limit`；
4. `cost = costOf(g, owned)`；
5. `(worth["kill"] or 0) >= cost`；
6. `worth("-", { kill = cost })` → `player:set(ownedKey(key), owned + 1)` → `applyGoods(player, key)`；
7. `alerter.message(player, 结果)`，随后 `async.call(player, function() UIKit("xlik_shop"):refresh(makeData(player)) end)`。

### 5.5 商品实现细节（`applyGoods`）

```lua
local function applyGoods(player, key)
    local hero = player.hero
    if (key == "talent_point") then
        player:set("天赋点", (player:get("天赋点") or 0) + 1)
    elseif (key == "talent_refresh") then
        player:set("天赋刷新点", (player:get("天赋刷新点") or 0) + 1)
    elseif (key == "all_attr") then
        hero:set("str", "+=" .. ALL_ATTR_VALUE)
        hero:set("agi", "+=" .. ALL_ATTR_VALUE)
        hero:set("int", "+=" .. ALL_ATTR_VALUE)
    elseif (key == "buff_rage") then
        --- 百分比只能用自定义 Buff(unit:set 不支持 ampl 回退)
        Buff({
            key = "shop_rage", object = hero, signal = buffSignal.up,
            name = "狂暴药剂", icon = ICON_RAGE, duration = 60,
            description = { "攻击力提升30%" },
            purpose = function(o)
                o:ampl("attack", (o:ampl("attack") or 0) + 30)
            end,
            rollback = function(o)
                if (false == class.isDestroy(o)) then
                    o:ampl("attack", (o:ampl("attack") or 0) - 30)
                end
            end,
        })
    elseif (key == "buff_haste") then
        job.attrBuff(hero, "shop_haste", "疾风药剂", ICON_HASTE, 60, "attackSpeed", 30,
            buffSignal.up, { "攻击速度提升30" })
    elseif (key == "buff_bounty") then
        Buff({
            key = "shop_bounty", object = hero, signal = buffSignal.up,
            name = "赏金符", icon = ICON_BOUNTY, duration = 120,
            description = { "金币加成提升100%" },
            purpose = function(o)
                local pla = o:owner()
                pla:set("金币加成%", (pla:get("金币加成%") or 0) + 100)
            end,
            rollback = function(o)
                if (false == class.isDestroy(o)) then
                    local pla = o:owner()
                    pla:set("金币加成%", (pla:get("金币加成%") or 0) - 100)
                end
            end,
        })
    elseif (key == "challenge_gold") then
        cornerChallenge.spawnForPlayer("gold", player, true)
    end
end
```

- `Buff` 同 key 重复购买 = 刷新时长（不叠加），所以 BUFF 类限购只是限制次数。
- `英雄无效`（死亡/未选）时，数值/BUFF 类商品直接拒绝并退款？**不退款**：校验阶段（第 1 步）已要求英雄有效，因此 `applyGoods` 内不再做二次判断。
- `challenge_gold` 走 `cornerChallenge.spawnForPlayer("gold", player, true)`：第 3 个参数为新增的 `force`，跳过充能检查与充能消耗。
