# 单局时长控制 + 挑战充能/限时 方案

> 说明：本文档为**已实施方案**记录。评审通过后又追加了两处调整——「挑战改为充能层数制」「挑战怪击杀限时 + 头顶倒计时」——已同步到 3.3 / 3.4 / 3.5 与决策表。

---

## 一、目标

1. **单局时长控制在 30 分钟以内**。
   - 统计口径（已确认）：只算「通关用时」= 最后一个 BOSS 出现时刻 + 击杀耗时，**不含通关后 7 分钟打存档的等待**。
2. **给 金币/经验/天赋/宝物 四种挑战添加充能限制**（像技能层数）：开局从 0 层开始充能、每类上限 3 层、有层才能发起，以此限制单局挑战次数。
3. **给挑战怪添加击杀限时**：每只挑战怪 60 秒内未击杀即挑战失败，并在其头顶信息牌显示倒计时。

---

## 二、现状分析（含代码位置）

### 2.1 单局时长的构成

| 要素 | 现值 | 位置 |
|------|------|------|
| BOSS 出生间隔 | 6 分钟（每个 BOSS 重置） | [boss_show_countdown](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/BOSS.lua#L379-L411) `local seconds = 6 * 60` |
| BOSS 击杀时限 | 3 分钟（超时判负） | [boss_kill_countdown](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/BOSS.lua#L282-L291) `kill_seconds = 60 * 3` |
| 通关需击败 BOSS 数 | N1–2=4 / N3–4=5 / N5–6=6 / N7+=7 | [diff_boss_count](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/BOSS.lua#L49-L51) |
| 通关后强制结束等待 | 7 分钟 | [WIN_END_DELAY](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/通关失败.lua#L9-L14) |

**新口径公式**：单局时长 = `BOSS数 × 出生间隔 + 击杀耗时(≤3分)`（不含通关后 7 分钟）。

**关键结论**：时长主因是 **BOSS 出生间隔**（每多一个 BOSS 就多一个间隔），通关后 7 分钟不参与本口径。

### 2.3 与「速通」口径的关系

- 本局用时 [playedSeconds](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E5%AD%98%E6%A1%A3%E6%B5%81%E7%A8%8B.lua#L1630-L1640) 每秒累加；速通判定在**通关当刻**（`slkc_game_clear`）读取，见 [writeResult](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E5%AD%98%E6%A1%A3%E6%B5%81%E7%A8%8B.lua#L1878-L1881)。→ **天然不含通关后 7 分钟**，与新口径一致，无需改动这一处。
- 但速通阈值公式 [speedTimeMinutes](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E5%AD%98%E6%A1%A3%E6%B5%81%E7%A8%8B.lua#L146-L152) 内嵌了 `bossCount(diff) * 6 + 3`，其中的 `6` 就是 BOSS 出生间隔。**改动出生间隔后此处会与节奏脱节，需同步**。

## 三、改动方案

### 3.1 BOSS 出生间隔 6 → 5 分钟

- **文件**：`projects/demo/scripts/process/BOSS.lua`
- **改动**：`boss_show_countdown` 中
  ```lua
  local seconds = 6 * 60   -->   local seconds = 5 * 60
  ```
  并加注释说明「为把单局时长压到 30 分钟以内由 6 分钟调整为 5 分钟」。
- **改动后时长（新口径）**：

| 难度 | BOSS 数 | 通关时刻 | 单局时长 |
|------|--------|---------|---------|
| N1–N2 | 4 | 20 min | 20–23 min ✅ |
| N3–N4 | 5 | 25 min | 25–28 min ✅ |
| N5–N6 | 6 | 30 min | 30–33 min ⚠️ 最坏略超 |
| N7+ | 7 | 35 min | 35–38 min ❌ |

> N5+ 若也要严格 ≤30 分钟，需再动 [WIN_END_DELAY](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/%E9%80%9A%E5%85%B3%E5%A4%B1%E8%B4%A5.lua#L9-L14)（本次**不改**）或进一步压缩。本方案按「N1/N2 达标」交付。

### 3.2 速通阈值同步对齐（6 → 5）

- **文件**：`projects/demo/scripts/process/存档流程.lua`
- **改动**：`speedTimeMinutes` 中
  ```lua
  local normal = bossCount(diff) * 6 + 3   -->   local normal = bossCount(diff) * 5 + 3
  ```
  并加注释：倍率 = BOSS 出生间隔（分钟），必须与 `BOSS.lua` 保持一致。
- **阈值变化**（`(bossCount*间隔+3-15)/2+15`）：

| 难度 | BOSS 数 | 旧阈值(6分) | 新阈值(5分) |
|------|--------|-----------|-----------|
| N1–N2 | 4 | 21 min | 19 min |
| N3–N4 | 5 | 24 min | 21.5 min |
| N5–N6 | 6 | 27 min | 24 min |
| N7+ | 7 | 30 min | 26.5 min |

### 3.3 挑战充能（服务端）· 已实施

- **文件**：`projects/demo/scripts/globals/setup/四角挑战.lua`

在「五-1 自动挑战」之后、`lockOnTarget` 之前，新增小节「五-2 挑战充能」：

**a. 常量与状态**
```lua
--- 充能层数上限
local CHARGE_MAX = 3
--- 每充能 1 层所需秒数: 金币/经验/天赋 60, 宝物 180
local CHARGE_CD = { gold = 60, exp = 60, talent = 60, treasure = 180 }
--- 充能刷新周期(秒)
local CD_TICK = 0.5

--- 当前充能层数: charge[key][playerIndex] = 0..CHARGE_MAX
cornerChallenge.charge = {}
--- 距下一层的已充能秒数: chargeProgress[key][playerIndex] = 秒
cornerChallenge.chargeProgress = {}
--- 充能计时器(单例)
local chargeTimer = nil
```

**b. 推送（服务端 → 该玩家客户端）**
```lua
local function pushCharge(key, player, charge, progress, need)
	async.call(player, function()
		if (type(isUIKit) == "function" and true == isUIKit('slkc_challenge')) then
			UIKit('slkc_challenge'):setCharge(key, charge, CHARGE_MAX, progress, need)
		end
	end)
end
```
> 依据：`async.call(player, fn)` 最终走 [japi.AsyncExec](file:///d:/Lua/xlik-jade/library/japi/lk.lua#L722-L733)，由 [asyncExec.lua](file:///d:/Lua/xlik-jade/exe/lib/embeds/lua/start/asyncExec.lua) 只在该玩家机器上执行 `localPlayerIndex` 的队列 → UI 更新只出现在目标玩家客户端。

**c. 充能累加（每 CD_TICK 秒一次）**
```lua
local function chargeTick()
	for _, tp in ipairs(cornerChallenge.types) do
		local key = tp.key
		local need = CHARGE_CD[key] or 0
		-- 按 1..player.startQuantity 遍历在线玩家; 未满层则累加进度, 满 1 层则 +1 层
		--   进度与层数写回 cornerChallenge.charge / chargeProgress, 并 pushCharge 刷新客户端
	end
end
```
> **计时器常驻**（不在满层时销毁）：避免开局 `player.startQuantity`/`isPlaying` 尚未就绪时计时器被销毁后**永不再充能**；通关时由 `clearAll` 销毁。

**d. 消耗层数**
```lua
local function useCharge(key, player)   -- 发起成功后调用: 层数 -1, 确保计时器在跑, 并推送
```

**e. 生成入口加充能校验**（`spawnForPlayer` 中，英雄校验之后、宝物等级门槛之前）
```lua
--- 充能检查: 没有可用层数直接拒绝(像技能层数)
local curCharge = (cornerChallenge.charge[key] or {})[player:index()] or 0
if (curCharge <= 0) then
	alerter.message(player, ('|cffff0000[%s]:充能中, 暂无可用次数!|r'):format(tp.name))
	return
end
```
并在**生成成功后**（`playSpawnPerform` 之后）调用 `useCharge(key, player)`。

**f. 自动挑战接入**（`autoStep` 中，取到 `pi` 之后）
```lua
--- 充能不足: 静默等待(不加打扰提示, 避免每秒刷屏)
local curCharge = (cornerChallenge.charge[key] or {})[pi] or 0
if (curCharge <= 0) then return end
```
> 必须加在 `autoStep` 里：自动模式每秒轮询会调用 `spawnForPlayer`，若不在入口前静默拦截，会每秒弹一次提示。

**g. 开局进入充能**
```lua
function cornerChallenge.setup()
	--- 开局四个挑战直接进入充能(从 0 层开始, 按冷却逐层回充)
	ensureChargeTimer()
	...
end
```

**h. 通关清除**（`clearAll` 末尾）
```lua
--- 清除挑战充能(通关后不再需要)
cornerChallenge.charge = {}
cornerChallenge.chargeProgress = {}
if (nil ~= chargeTimer) then class.destroy(chargeTimer); chargeTimer = nil end
```

### 3.4 挑战充能（客户端 UI）· 已实施

- **文件**：`vendor/assets/war3mapUI/slkc_challenge/main.lua`

**a. 本地状态**
```lua
--- 各入口充能状态(本地展示; 由服务端 setCharge 下发)
local chargeState = {}   -- { charge, max, progress, need }
```

**b. `challenge` 加充能拦截**（点击/热键共用）
```lua
local function challenge(key, symbol)
    if (false == visible) then return end
    local st = chargeState[key]
    if (type(st) == "table" and (st.charge or 0) <= 0) then
        sound.vcm("war3_Error")   -- 无可用层数
        return
    end
    sound.vcm("war3_MouseClick1")
    sync.send(symbol, { PlayerLocal():index() })
end
```
（两处调用改为 `challenge(e.key, e.symbol)`）

**c. `onSetup` 给每个按钮加遮罩 + 层数文本**
```lua
btn:mask(X_UI_BLACK):maskAlpha(170)
self.chargeTexts[i] = UIText(kit .. ":" .. e.key .. ":ct", btn)
    :relation(UI_ALIGN_TOP, btn, UI_ALIGN_TOP, 0, -0.002)   -- 顶部居中
    :textAlign(TEXT_ALIGN_CENTER):fontSize(9):text(''):show(false)
```

**d. 新增 `ui:setCharge`（服务端下发入口）**
```lua
function ui:setCharge(key, charge, max, progress, need)
    chargeState[key] = { charge = charge, max = max, progress = progress, need = need }
    -- 未满层: 遮罩比例 = progress/need(本层充能进度); 满层: 无遮罩
    -- 顶部文本 = "charge/max", 0 层红色, 其余金色
end
```

## 四、决策与假设（已与用户确认）

| 项 | 决策 |
|----|------|
| 单局时长口径 | 通关用时（**不含**通关后 7 分钟打存档） |
| BOSS 出生间隔 | 6 → **5 分钟** |
| 速通阈值 | 同步按 **5 分钟**重算（`*5+3`） |
| 充能模型 | **电池式**：开局 0 层，上限 3 层，用 1 层扣 1 层，按时间回充 |
| 充能间隔 | 金币/经验/天赋 **60s**；宝物 **180s**（每回充 1 层） |
| 充能范围 | **手动点击与自动挑战共用**同一充能 |
| 挑战怪击杀限时 | **60 秒**；超时挑战失败（怪消失、不发奖、充能不返还） |
| 倒计时显示 | 挑战怪头顶信息牌「N级 名称 **[剩余秒]秒**」 |
| 通关后等待 | **保持 7 分钟不变** |

## 五、明确不做

- 不改 `WIN_END_DELAY`（通关后 7 分钟）。
- 不动宝物挑战原有的「英雄等级门槛」与「15 次上限」（充能在其之上叠加）。
- 不改平台胜负上报 / 结算流程。

## 六、验证步骤

1. **静态检查**：改动文件 `GetDiagnostics` 无报错。
2. **充能（手动）**：开局四个按钮显示 `0/3`（红色）并逐步回充；无层时点击只出 `war3_Error` 且不生成怪；攒到层数后点击可发起，发起成功扣 1 层。
3. **充能（自动）**：右键开启自动挑战 → 无层时静默等待，攒到层后自动开下一只，且**不会每秒刷提示**。
4. **充能（服务端兜底）**：绕过客户端直接触发同步事件时，服务端应拒绝并提示「充能中, 暂无可用次数!」。
5. **击杀限时**：挑战怪出生后头顶出现 `[60秒]` 并逐秒递减；60 秒内未击杀 → 怪消失、无奖励、充能不返还、收到失败播报；限时内击杀 → 正常发奖且倒计时停止。
6. **通关清除**：通关后挑战按钮充能/挑战怪/计时器一起清空，无残留计时器。
7. **时长**：N1/N2 实跑记录「通关用时」，应落在 20–23 分钟（不含通关后 7 分钟）。
8. **速通**：验证新阈值下（N1 = 19 min）提速通关可正常判定速通。
