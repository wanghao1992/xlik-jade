# 随机事件系统重构方案

## 一、需求与决策（已确认）

| 项 | 决策 |
| --- | --- |
| 触发方式 | **A 杀敌里程碑自动弹出**：达标（50/150/400，之后每 400）立即自动弹出事件 UI，无需再点技能 |
| 事件池 | **A 全部重写**：全部替换为 War3 主题事件（赏金/伏击/符文/中立生物袭击/环境事件），风险与收益并存，少纯数值堆砌 |
| 展示 | 新 UI 套件：事件名 + 事件内容 + 【接受】【忽略】两按钮；接受=立即生效，忽略=跳过本次 |
| 技能入口 | 「随机事件」技能从英雄/职业模板移除（不再作为入口），角标/光晕逻辑删除 |

## 三、系统设计

### 3.1 触发链路（自动弹出）

```
杀敌 unitDead 事件(小怪)
  → 累计 totalKill 跨越门槛(50/150/400…)
  → 同步环境抽取 1 个事件: randomEvent.rollOne(pla)  (按 weight 加权, 过滤 multi/minWave)
  → 存入 pending[pla] = def(浅拷贝)
  → async.call(pla, 打开 xlik_event 套件, 传入 {事件名, 描述})
```

- 忽略：`sync.send("xlik_event_ignore",{pla})` → 服务端校验 pending 存在 → 清空 pending → 本地关闭套件。该次里程碑即消耗。
- 接受：`sync.send("xlik_event_accept",{pla})` → 服务端校验 → `def:apply(pla, hero)` → 清空 pending → 本地关闭套件。
- 防重复：`pending[pla]` 非空时新里程碑不再弹（老图同口径）；英雄死亡/无英雄时不弹。

### 3.2 新 UI 套件 `xlik_event`

- 新建 `vendor/assets/war3mapUI/xlik_event/main.lua`（套件名 `xlik_event`），并在 `projects/demo/assets/project.lua` 注册 `assets_ui("xlik_event")`。
- 参照 `xlik_learn` 面板结构（居中 layer、标题、内容区、底部按钮），仅一个事件：
  - 标题：事件名（按稀有度着色：普通白 / 稀有金 / 史诗紫红）。
  - 内容区：事件描述（折行 `foldDesc` 复用），可选图标。
  - 底部两按钮：【接受】在左、【忽略】在右（FDF `LK_SLKC_BUTTON_PANEL`）。
- 接口：`ui:open(data{playerIndex,name,desc,rarity})` / `ui:close()` / `ui:isOpen()`。
- 打开时接管技能栏（隐藏 xlik_plate 技能栏），关闭时延迟 2 帧恢复（照 `xlik_learn`）。

### 3.3 同步协议

| key | 数据 | 说明 |
| --- | --- | --- |
| `xlik_event_accept` | `{玩家index}` | 接受事件 → 服务端执行 `apply` |
| `xlik_event_ignore` | `{玩家index}` | 忽略事件 → 服务端清 pending |

### 3.4 事件数据表结构调整（随机事件数据.lua）

```lua
{
    name = '事件名',            -- UI 标题
    desc = function(self) ... end,  -- 事件内容(UI 正文), 支持函数
    rarity = 'common',          -- common普通 / rare稀有 / epic史诗(控制颜色与权重倾向)
    weight = 1,                 -- 抽取权重(默认1)
    multi = false,              -- 仅多人游戏出现(单人过滤)
    minWave = 1,                -- 最低波次(可选, 用 mobExtra.avgWave 过滤)
    create = function(self, pla) end,  -- 抽取时确定本次数值(可选)
    apply = function(self, pla, hero) end,  -- 接受时触发
}
```

- 旧字段 `tips` 更名为 `desc`（语义变为"事件内容"）；`apply` 签名不变。
- `tipsText`（去色码）不再需要，由套件直接渲染 `desc`（支持 |c 颜色码）。

### 3.5 服务端改动（随机事件.lua）

- 保留：`needTotal`/`earnedByKills`/`earned`（杀敌门槛换算）、`copyDef`、`eventAttr`。
- 删除：原生 Dialog 面板 `open`/`show`/`buildButtons`/`tipsText`、刷新/追击模式超时逻辑、`pending` 由对话框改为"待处理事件"。
- 新增：
  - `randomEvent.rollOne(pla)`：加权抽 1 个（过滤 multi/minWave/无英雄），`create` 定值，返回拷贝。
  - `randomEvent.pop(pla)`：弹出（打开套件），服务端触发点调用。
  - `sync.receive("xlik_event_accept"/"xlik_event_ignore")` 处理。
  - 伏击怪生成辅助 `spawnMobAround(pla, waveMul, count)`：仿 [刷怪.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/process/刷怪.lua#L376-L412) 建怪、按 `mobExtra.avgWave` 缩放、置 `小怪=true`、登记 `mob_table`（`game.method.getMobTable()[mob:id()]=mob`）。
- 杀敌监听事件保留门槛检测，但 `earned > 上次` 时改为调 `randomEvent.pop(owner)`（不再累加"次数"、不再播报"点击技能栏"）。

### 3.6 技能入口移除

- [英雄.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/unit/英雄.lua#L13) 与 [职业.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/unit/职业.lua#L24) 中移除 `[4] = TPL_ABILITY.RANDOM_EVENT`（槽位后移或留空，按现状留空即可）。
- 删除 [随机事件.lua(ability)](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/tpl/ability/随机事件.lua) 文件与 `TPL_ABILITY.RANDOM_EVENT` 定义。
- `image_self.lua` 中 30 帧事件按钮光晕资产不再被引用（保留资源文件，构建仅提示未使用，可后续清理）。

## 六、验证步骤

1. 静态：`luac -p` 校验改动文件。
2. 实机（用户自行 `xlik.exe run demo -l`）：
   - 杀敌 50/150/400… 达标时**自动弹出**事件套件（不再需要点技能）。
   - 套件显示事件名（按稀有度着色）+ 事件内容 + 【接受】【忽略】。
   - 点【接受】→ 事件效果立即生效，套件关闭；点【忽略】→ 无效果，套件关闭，该次里程碑消耗。
   - 事件效果抽验：N6 食尸鬼夜袭刷怪可击杀得奖励；N19 暴风雪全图减速；N14 生命符文回血+上限；N27 恶魔契约永久 ±。
   - 英雄死亡/无英雄时不弹；事件待处理期间不重复弹。
   - 技能栏不再有「随机事件」技能，原槽位正常。
3. 回归：`eventAttr` 属性口径与 存档流程/天赋 保持一致，伤害/金币/等级/伏击怪效果与框架机制兼容。
