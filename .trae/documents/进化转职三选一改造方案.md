# 进化转职三选一改造方案

参考实现：`D:\Lua\不思议生存`（英雄进化选择面板 + 技能传承机制）
目标文件：`d:\Lua\xlik-jade\projects\demo`

## 一、需求与目标

把现有"进化转职"从「默认只抽 1 个职业直接转职 + 原生 Dialog 选择」改造为：

1. **进化触发时三选一**：固定展示 3 个候选职业（可刷新 1 次），玩家自选。
2. **可选保留 1 个旧职业技能**：选定新职业后，可从当前职业的 3 个技能中挑 1 个保留，其余槽位用新职业的技能。
3. **自定义卡片面板**：仿「天赋三选一」（`xlik_learn`）的卡片式面板，不暂停游戏、卡片展示职业图标/名称/属性/技能说明。
4. **面板内「不再进化」开关**：替代现有「是否继续转职？」弹框。

核心诉求：在随机里加一点自选，让玩家玩得更舒服。

## 三、总体设计

### 3.1 新交互流程

```
杀敌达标
 └─ jobFlow.start(pla)
     ├─ 抽取 3 个候选职业(排除当前职业)
     └─ async.call(pla, UIKit("xlik_job"):open(candidates, opts))
          ├─ [点职业卡]  高亮选中该职业, 同时展开底部"技能继承"区
          ├─ [点旧技能]  选中 1 个要保留的旧技能(可再点取消)
          ├─ [点确认进化] sync.send("xlik_job_confirm", {playerIndex, jobName, keepSkill})
          ├─ [点刷新(n)] sync.send("xlik_job_refresh", {playerIndex})
          └─ [点不再进化开关] 本地切换, 确认时随确认一起提交
 └─ 服务端 sync.receive:
     ├─ xlik_job_confirm → 校验候选/技能 → jobFlow.change(pla, jobName, keepSkill) → 关闭面板
     ├─ xlik_job_refresh → 扣刷新次数 → 重抽(排除当前 3 个) → 面板刷新
     └─ 超时 30 秒 → 自动选第一个候选(不保留技能) → change → 关闭面板
```

### 3.2 技能装配规则（decision）

最终技能栏固定 3 个，槽位 `{1,2,3}` = Q/W/E：

| 情况 | 槽位1(Q) | 槽位2(W) | 槽位3(E) |
|---|---|---|---|
| 未保留旧技能 | 新职业技能[1] | 新职业技能[2] | 新职业技能[3] |
| 保留旧技能 K | 新职业技能[1] | 新职业技能[2] | K（保留的旧技能） |
| 保留 K 且 K 与新技能[1]/[2] 同名 | 新职业去重后的第1个 | 新职业去重后的第2个 | K |

去重规则：先从新职业技能列表中剔除与保留技能同名的项，再取前 2 个填槽位 1/2；不足 2 个时（同名过多）用新职业剩余技能按原顺序补齐；仍不足则留空。

### 3.3 「不再进化」开关

- 面板底部提供「是否继续进化」开关按钮（默认"是"），点击切换为"否"。
- 提交确认时若开关为"否" → 额外执行 `pla:set('不再转职', true)`，此后 `jobFlow.start` 直接返回。
- 结论：**移除** `askContinue` 弹框逻辑与 `job_continue_ask_count` 的使用（配置项保留不删，避免其它引用报错；如无引用则一并清理）。

### 3.4 候选与刷新

- 候选数量沿用现有算式 `1 + pla:get('可选转职数量')`，仅把默认值从 `0` 改为 `2`（即默认 3 选 1）；商城道具仍可继续增加候选。
- 刷新沿用 `job_refresh_times`（默认 1），刷新时重抽 3 个并**排除当前这 3 个**，尽量不重复。

### 4.2 `projects/demo/scripts/process/转职.lua`

**改造点：**

1. **`roll(pla, num, exclude)`** — 新增 `exclude`（`{职业名=true}`），抽卡时一并排除，供刷新时排除当前候选。

2. **`applySkills(hero, data, keepSkillName)`** — 由"全部替换"改为按 3.2 规则装配：
   - 先卸掉英雄身上所有属于 `TPL_ABILITY.JOB` 的技能（逻辑不变）。
   - 计算最终技能列表 `finalSkills`（去重后），按 `JOB_ABILITY_INDEX[i]` 依次 `slot:insert`。
   - `keepSkillName` 为空时等价于原行为。

3. **`jobFlow.change(pla, jobName, keepSkillName)`** — 新增第 3 个可选参数并透传给 `applySkills`；在返回结果事件 `slkc_job_change` 的 `evtData` 中追加 `keepSkillName`。
   - `-job 职业名` 测试命令（[command.lua](file:///d:/Lua/xlik-jade/projects/demo/scripts/globals/setup/command.lua#L66)）保持 2 参调用兼容。

4. **新增 `jobFlow.oldJobSkills(pla)`** — 从英雄技能栏实时读取当前职业技能（`slot:storage()` 中 `tpl:name()` 属于 `TPL_ABILITY.JOB` 的项），返回 `{ {name, icon, desc}, ... }`，供面板"技能继承"区展示。首次转职返回空表。

5. **`jobFlow.candidateData(data)`** — 把一条 `game.config.jobs` 记录转成面板数据：
   ```lua
   { key = data.name, name = data.name, icon = data.icon,
     primary = '力量'|'敏捷'|'智力',
     attrs = '力量5 敏捷5 智力5',
     skills = { {name='剑刃风暴', icon=..., desc=...}, ... } }  -- 取自 TPL_ABILITY.JOB[技能名]
   ```

6. **`openPanel(pla, candidates)`**（替代 `openSelect`）— 组装数据 + `opts`，`async.call(pla, ...)` 打开 `xlik_job` 面板；注册超时兜底（`job_flow_timeout`）自动选第一个候选。
   ```lua
   local opts = {
     playerIndex = pla:index(),
     refreshLeft = pla:get('转职刷新次数') or 0,
     keepEnable = (cfg('job_keep_skill_enable', true) == true) and (#oldSkills > 0),
     oldSkills = oldSkills,     -- 旧职业技能(可保留候选项)
     noEvolve = false,
   }
   ```

7. **新增 `sync.receive("xlik_job_confirm" / "xlik_job_refresh")`**（照 `天赋.lua` 范式）：
   - `confirm`：校验 `jobName` 在本次候选内（用 `pla:set('转职候选', '名1|名2|名3')` 存同步字段）、`keepSkill` 属于 `oldJobSkills` → 调 `jobFlow.change`；若 `noEvolve` 为真则同时 `pla:set('不再转职', true)`；最后 `async.call(pla, UIKit:close)`。
   - `refresh`：校验流程中且刷新次数 > 0 → 扣次数 → 重抽并写回 `转职候选` → `async.call(pla, UIKit:refresh(items, opts))`。

8. **`jobFlow.start`** — 抽 3 个候选后：`#candidates == 0` 时解除"转职流程中"；否则一律走 `openPanel`（不再有"单候选直接转职"与 `askContinue` 分支，`skipAsk` 参数保留但不再使用）。同时写入 `pla:set('转职候选', 拼接串)`。

9. **删除 `askContinue`** 与 `REFRESH_VALUE` 等仅服务于 Dialog 的常量。

## 五、假设与决策

| 项 | 决策 | 理由 |
|---|---|---|
| 保留技能的槽位 | 固定放在槽位 3（E） | 新职业技能 [1][2] 保持 Q/W 手感一致，旧技能占末位干扰最小 |
| 保留技能数量 | 最多 1 个，可再次点击取消 | 用户明确选择"只保留 1 个旧技能" |
| 保留技能是否跨局存档 | 否，仅本局内存 | 与现有 `职业名`/`转职次数` 一致，走 `player:set` |
| 首次转职 | 不显示技能继承区（`keepEnable=false`） | 初始英雄 `HERO_1` 无职业技能 |
| 候选数量 | 默认 3（`job_optional_count=2`），仍受商城道具影响 | 保留现有"可选转职数量"体系，兼得"固定三选一"与可扩展 |
| `askContinue` | 移除，由面板「是否继续进化」开关替代 | 参考图把该开关做进面板，减少一次弹窗打断 |
| UI 环境 | 面板在本地（异步）渲染，逻辑在服务端（同步）校验 | 与天赋三选一完全一致的既有范式 |
| 超时兜底 | 保留 30 秒 → 自动选第一个候选、不保留技能 | 避免玩家挂机卡住转职流程（沿用现有设计） |

## 六、验证

1. **静态检查**：对改动/新增的 `.lua` 文件执行 `luac -p`（不执行打包命令 `xlik.exe run demo -l!`，由用户自行打包测试）。
2. **用户自测清单**（打包后）：
   - `/job`（或杀敌达标）→ 面板弹出，展示 3 个候选职业，卡片含图标/名称/属性/3 个技能。
   - 点职业卡 → 高亮选中，技能继承区展开显示当前职业技能。
   - 点旧技能 → 选中；点确认进化 → 转职成功，技能栏 = 新技能[1] + 新技能[2] + 保留的旧技能。
   - 不选技能直接确认 → 技能栏 = 新职业 3 个技能。
   - 点刷新(1) → 候选重抽且与上一组不同，次数减为 0 后按钮不再可用。
   - 点「是否继续进化」切到"否"→ 确认后不再触发进化面板。
   - 首次转职 → 技能继承区不显示。
   - 挂机 30 秒不操作 → 自动选第一个候选并关闭面板。
   - `-job 职业名` 测试命令仍可用（不保留技能）。
